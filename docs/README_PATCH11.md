# 패치 11 — 챗봇 명령이 실행되지 않던 문제

패치 10 위에 덮으십시오. 패치 7~10 내용을 모두 포함합니다.

## 무엇이 문제였나

```
사용자: LCV-01 인터락 조회해줘
챗봇:   인터락 정보를 조회하겠습니다.     ← 그리고 아무 일도 안 일어남
```

이번에는 태그 표기 문제가 아닙니다. `LCV-01` 은 하이픈까지 정확했고
규칙 엔진은 `type=interlock, tag=LCV-01` 을 정확히 뽑아냈습니다.

**LLM 이 규칙보다 우선권을 갖고 있었던 것이 원인입니다.**

qwen2.5:7b 는 이 작업에서 규칙보다 못합니다. 같은 문장에
`{"type":"chat","reply":"인터락 정보를 조회하겠습니다."}` 를 돌려주는데,
`type=chat` 이면 화면은 실행하지 않습니다. 친절한 문구만 남고 동작은
사라집니다. "사용법" 이 안 나오던 것도 같은 이유입니다.

## 고친 것 — 규칙 우선, LLM 은 보조

순서를 뒤집었습니다.

1. **규칙 엔진을 먼저 돌립니다.** 실행 가능한 의도가 나오면 그대로 씁니다.
2. 규칙이 못 알아들은 표현에 **한해서만** LLM 에 물어봅니다.
3. LLM 결과도 태그 검증을 거칩니다. 태그가 필요한데 없으면 되묻습니다.
4. LLM 도 실패하면 규칙의 안내 문구를 씁니다.

규칙 엔진은 이 앱이 지원하는 명령을 정확히 덮고 **결정적**입니다.
시연에서 같은 문장에 같은 동작이 나온다는 점도 중요합니다.

응답에 `engine` 필드가 실려 어느 경로였는지 알 수 있습니다
(`rule` / `llm` / `rule_fallback`).

### 확인 결과 (LLM 이 계속 무의미한 chat 을 뱉는 상황에서)

| 입력 | 결과 |
|---|---|
| `LCV-01 인터락 조회해줘` | interlock / LCV-01 |
| `LCV 01 인터락 보여줘` | interlock / LCV-01 |
| `사용법` | help + 가이드 문구 |
| `AIT-4002 산 잔량 알람 조회해줘` | diagnose / AIT-4002 |
| `LCV-01 인터락 원본 보여줘` | interlock_source / LCV-01 |
| `ZZZ-99 인터락 조회` | chat — 없는 태그라고 답함 |
| `오늘 날씨 어때` | chat — 사용 예시 안내 |

## selfcheck 에 회귀 검사 추가

```
[OK] 챗봇 명령 실행 [주입]   규칙 우선 — LLM 오작동에도 명령 실행
```

LLM 이 항상 `type=chat` 만 돌려주는 상황을 주입하고, 그래도 명령이
실행되는지 확인합니다. 같은 문제가 다시 생기면 시연 전에 잡힙니다.

## 확인

```cmd
run_check.bat
```

`챗봇 명령 실행 [주입]` 항목이 새로 나옵니다.

백엔드를 재시작한 뒤 챗봇에서 시험해 보십시오. 하단 칩(`사용법`,
`알람 조회`, `인터락`, `실물 인터락`, `원본 리스트`)이 모두 실제로
화면을 움직여야 정상입니다.

## 주의

이번 selfcheck 출력에서 `다양성 설정` 이 `kind` 로 나왔습니다.
`COPILOT_DIVERSIFY=off` 가 없는 창에서 돌리신 것입니다. 반드시
`run_check.bat` / `run_eval.bat` 으로 돌리십시오 — 이 값이 빠지면
검색 성능이 33/45 에서 29/45 로 떨어집니다.
