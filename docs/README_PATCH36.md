# PATCH 36 — 「정지해줘」 만으로는 멈추지 못했다

2026-09-11 · 배포에서 사용자가 발견

## 문제

```
사용자: P-5101A 공정 화면 재생해줘
  AI  : P-5101A 공정 화면을 열어 시나리오를 재생합니다.

사용자: 정지해줘
  AI  : P-5101A 알람 조회를 실행합니다.          ← 알람 조회로 샜다
```

패치 33 에서 고친 것과 같은 자리다. 다만 **표현이 다르다.**

## 먼저 — 패치 35 의 회귀는 아니다

의심이 정당한 위치였으므로 대조했다. 정지 판정 표현은 패치 33·패치 35 직전·
현재가 **글자까지 같다.**

```
patch33 (203c098)  r"(시나리오|시뮬레이션|재생|공정\s*화면)[^\n]*(정지|멈춰|…)"
patch35 직전         같음
현재                 같음 (api/tools.py 의 GRAPHIC_STOP.trigger 로 옮겨졌을 뿐)
```

즉 **「정지해줘」 단독은 패치 33 에서도 동작한 적이 없다.** 되돌아온 것이
아니라, 처음부터 덮인 적이 없는 표현이다. 패치 33 의 규칙은 시나리오·
시뮬레이션·재생·공정 화면 중 한 낱말을 **함께** 요구했고, 그 가드도
`"시나리오 정지해주세요"` 처럼 낱말이 함께 있는 표현만 봤다. 사람이 실제로
하는 말 — 방금 재생을 시켰으니 목적어를 생략한 말 — 은 아무도 보지 않았다.

**고친 표현만 보는 가드는 고친 것만 지킨다.** 이번 건의 교훈은 여기다.

## 무엇을

### 1. 맥락을 본다 — 도는 중이면 낱말 하나로 멈춘다

`api/tools.py` 에 도구를 하나 더 둔다 (`stop_bare`, order 78).

**인터락 조회(75) 뒤**에 둔 것이 이 도구의 절반이다. 순서로 가른다 —
`"P-5101A 정지 인터락 조회해줘"` 는 인터락이 먼저 가져가고, 인터락이라는
낱말이 없는 `"정지해줘"` 만 여기로 내려온다. 예외 처리로 걸러내지 않는다.

도는 중인지는 **화면만 안다.** 사람이 화면의 버튼을 직접 눌러도, 조작을
만져 시나리오가 저절로 멈춰도 서버는 알 길이 없다. 그래서 짐작하지 않고
받아서 쓴다.

```
interlock_P-5101A.html   scnStart/scnStop 에서 부모에게 상태를 알린다
                         (scnNotify → postMessage, origin 검사)
App.jsx (InterlockView)  그것을 받아 ChatContext.graphic 에 실어 보낸다
api/server.py            규칙이 그 맥락을 보고 판정한다 (ChatContext.graphic)
```

### 2. 맥락이 없으면 되묻는다 — 알람 조회로 실행하지 않는다

```
사용자: 정지해줘                       (시나리오가 돌지 않는 상태)
  AI  : 시나리오를 멈추실 건가요, P-5101A 정지 인터락을 조회하실 건가요?
        · 시나리오 정지 — "시나리오 정지해줘"
        · 인터락 조회 — "P-5101A 정지 인터락 조회해줘"
```

어느 쪽인지 모를 때 **실행한 것**이 이 사고의 본체다. 근거가 부족하면
답하지 않는다는 이 도구의 원칙을 명령 해석에도 적용한다 (패치 33 추기 1과
같은 자리). 문장에 태그가 있으면 그 태그로 되묻는다 — 사용자가 말한 설비를
우리가 바꿔 물으면 그것도 지어내는 것이다.

알람 어휘가 함께 있으면 넘긴다. SCADA 알람에는 `CMD STOP` 처럼 정지가 낱말로
들어 있어서, 그것까지 되물으면 조회가 막힌다.

### 3. 모델에게도 같은 맥락을 준다

`llm_user_line(req, text)` 가 사용자 줄에 `scenario=playing|open|none` 을
싣는다. 규칙만 맥락을 보고 모델은 못 보면, 규칙이 아는 표현은 되고 모르는
표현은 다시 엉뚱한 곳으로 간다 — 패치 33·35 가 가르친 것이다. 도구 목록의
`llm_rule` 에도 같은 판정을 적었으므로 스키마와 규칙이 갈라지지 않는다.

## 가드

**새 항목을 만들지 않고 패치 33 의 가드(`시나리오 정지 명령 [주입]`)를
넓혔다.** 놓친 자리를 그 가드가 보게 하는 것이 맞다. 56항목 그대로.

- 재생 중 맥락에서 **낱말 단독 6종**(정지해줘·멈춰줘·멈춰주세요·중지·스톱·
  정지)이 `stopScenario` 로 가는지
- 맥락이 없을 때(도는 중 아님 / 맥락 자체 없음) **실행하지 않고** 되묻는지,
  되묻기가 두 갈래를 모두 제시하는지, `generic` 이 아닌지(포괄 응답이면
  매뉴얼 검색으로 샌다)
- 문장의 태그로 되묻는지 (`XV-4101 정지해줘`)
- 조회 무손상 — 재생 중에도 정지 인터락 조회는 조회로, 알람 어휘의 STOP 은
  알람 조회로
- 화면이 상태를 알리는지 (public·dist 양쪽, 재생·정지 **양쪽**에서 호출,
  주석으로 꺼 두지 않았는지), App.jsx 가 그것을 받아 맥락에 싣는지,
  빌드본이 원본보다 오래되지 않았는지
- 모델에게 맥락이 가는지 (`scenario=playing`)

가드가 회귀를 잡는지 5종을 심어 확인했다.

```
낱말 단독 규칙 제거 (33 상태) → 재생 중인데 '정지해줘' 가 diagnose 로 갑니다
화면 맥락 무시               → 재생 중인데 '정지해줘' 가 chat 로 갑니다
맥락 없을 때 되묻지 않음       → 재생 중인데 '정지해줘' 가 diagnose 로 갑니다
모델에게 맥락 미전달           → 모델에게 재생 상태가 가지 않습니다
화면이 상태를 안 알림          → 상태 알림이 주석 처리되어 있습니다
```

마지막 것은 처음에 새어 나갔다. `scnNotify` 를 글자로만 세니 **주석으로 꺼
둔 줄이 그대로 통과했다.** 주석 여부를 함께 보게 고쳤다.

## 우리가 낸 사고 — 고치면서 화면을 죽였다

맥락을 싣는 `useEffect` 를 `graphicOpen` **선언보다 앞**에 두었다. 의존성
배열이 렌더 중에 평가되면서 `ReferenceError: Cannot access 'z' before
initialization` 이 나고 **화면이 통째로 죽었다.**

- `npm run build` 는 통과했다
- 자기 점검 56항목도 전건 통과했다 (소스의 글자를 보는 가드다)
- 배포했다면 첫 화면이 백지였다

**띄워 보고서야 콘솔에서 찾았다.** CLAUDE.md 7 의 "라우팅 판정만 보지 말고
실제로 호출한다" 가 화면에도 그대로 적용된다는 것을 이번에 배웠다. 선언
순서를 가드에 못 박고(`const [graphicOpen` 이 `playing: !!(graphicOpen`
보다 앞인지), 코드에도 이유를 주석으로 남겼다.

## 남는 것

- 맥락은 **인터락 조회 결과가 화면에 있을 때만** 올라간다. 사용자가 알람
  조회 탭으로 옮기면 그 결과가 화면 맥락을 덮어써서, 시나리오가 돌고 있어도
  「정지해줘」 는 되묻기로 간다. 되묻기는 틀린 답이 아니므로 이대로 둔다 —
  탭마다 맥락을 따로 쥐는 것은 화면 상태 관리를 다시 설계하는 일이다
- `그만`·`끄자` 같은 표현은 넣지 않았다. 정지 어휘를 넓히는 것은 끝이 없고,
  넓힐수록 조회를 잘못 끊는다. 지금은 **되묻기**가 그물이다
