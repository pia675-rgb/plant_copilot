# PATCH 35 — 도구 목록을 한 곳으로 (리허설 발견 6 포함)

2026-09-11 · 패치 33 이 남긴 구조적 한계를 닫는다

## 문제

패치 33 에서 "시나리오 정지해주세요" 가 P-5101A 정지 인터락 조회로 샜다.
고치고 나서 원인을 다시 보니, 같은 지식이 **두 곳**에 적혀 있었다.

```
규칙 (rule_intent)        무엇을 무엇으로 판정할지
LLM 명령 해석 스키마        모델이 고를 수 있는 것이 무엇인지
```

정지를 규칙에만 넣고 스키마에 넣지 않으면, **규칙이 아는 표현은 되고 모르는
표현은 모델이 받아 가장 가까운 것(인터락 STOP)으로 간다.** 모델이 이상한
선택을 한 것이 아니다 — 고를 것이 그것뿐이었다.

패치 33 노트에 이렇게 적어 두었다.

> 도구 하나를 늘리면 두 곳을 고쳐야 하고, 한 곳을 잊으면 오늘 같은 일이
> 난다. 도구 목록을 한 곳에서 정의하고 규칙·스키마가 그것을 읽는 구조가
> 맞다. 결선 과제로 남긴다.

그 결선 과제다.

## 무엇을

### 1. `api/tools.py` — 도구 목록의 유일한 정의

한 항목이 규칙·스키마·안내를 모두 갖는다.

| 무엇 | 누가 읽나 |
| --- | --- |
| `trigger` · `handler` · `order` · `before_tag` | 규칙 (`rule_intent`) |
| `summary` · `limit` · `llm_rule` · `schema_extra` | LLM 명령 해석 지침 |
| `help_pattern` · `help` | 기능 질문 안내 |
| `example` | 예시 줄 (포괄 응답·범위 밖 안내·가드) |
| `returns` · `llm_type` · `actionable` · `needs_tag` | 챗봇 계층의 실행 판정 |

**도구를 하나 늘릴 때 고칠 파일은 이 하나다.**

`order` 가 판정 순서다. 순서 자체가 사고의 기록이라 숫자 옆에 이유를 적었다
— 기능 질문은 명령보다 먼저(패치 29b), 시나리오 정지는 인터락보다 먼저
(패치 33), 탭 이동은 조회보다 먼저(이번).

### 2. 규칙은 그 목록을 차례로 물어본다

`rule_intent` 는 디스패처가 되었다. 판정 본체(`_r_*`)만 서버에 남고, 어떤
순서로 무엇을 물어볼지는 목록이 정한다. 태그 판정 전후를 `before_tag` 로
가른다 — 판넬명·단자 번호는 표기가 태그와 겹쳐 먼저 봐야 한다.

### 3. 스키마도 같은 목록에서 만들어진다

`llm_command_prompt(free)` 가 도구 목록에서 지침을 만든다. 도구가 늘면
모델이 고를 수 있는 것도 **저절로** 늘어난다.

함수로 뺀 이유가 하나 더 있다. **점검할 수 있어야 한다.** 지침을
`chat_help` 안에 묻어 두면 가드가 함수 소스를 문자열로 뒤지는 수밖에 없고,
그런 가드는 코드를 조금 옮기는 순간 보던 자리를 잃는다 — 실제로 패치 33 의
가드가 그렇게 되어 이번에 한 번 붉게 떴다. 가드도 만들어진 지침을 보도록
고쳤다.

목록을 합치면서 **스키마에 빠져 있던 판넬 조회(`type=panel`)가 함께
실렸다.** 규칙은 판넬 조회를 판정하는데 모델은 그것을 고를 수 없었다 —
패치 33 과 같은 모양의 구멍이 하나 더 있었던 것이다.

### 4. 반쪽 등록은 가져오기 시점에 죽는다

`tools.check()` 가 서버를 가져올 때 돈다. 표현만 적고 본체를 잊은 것, 실행
명령인데 스키마 설명이 없는 것, 기능 질문 표현만 있고 안내문이 없는 것을
잡고 **띄우고 죽는다.** 조용히 반쪽으로 도는 것보다 낫다 (CLAUDE.md 3-4).

## 새 도구 둘

### 탭 이동 (`navigate`)

"알람 조회 탭으로 이동해줘" 가 **알람 조회를 실행했다.** 조회라는 낱말이
들어 있으니 조회 규칙이 가져간 것인데, 사용자는 화면을 옮겨 달라고 했을
뿐이다.

- 탭 이름을 각 도구의 기능 질문 표현에서 읽는다 — 같은 낱말을 두 번 적지
  않는다
- **태그는 건드리지 않는다.** 옮기라는 말에 사이드바 태그까지 바뀌면 다음
  조회가 엉뚱한 설비를 본다
- 어느 탭인지 적혀 있지 않으면 옮기지 않고 되묻는다. 아무 데나 옮기는 것은
  지어내는 것과 같다
- `탭` 뒤에 이동을 뜻하는 말이 있어야 걸린다. "인터락 탭에서 뭘 볼 수
  있어?" 는 질문이므로 옮기지 않는다

### 범위 밖 질문 (`out_of_scope`)

9/2 리허설 발견 6번. 날짜 같은 질문이 매뉴얼 검색으로 흘러 무관한 인용이
붙었다. **검색이 답을 못 찾는 것이 아니라 비슷한 문구를 찾아 붙이는 것이
문제다.** 근거처럼 보이는 것이 붙으면 사람은 그것을 근거로 읽는다.

- 날짜·시각·요일·날씨·기온·환율·주가·뉴스를 끊는다. 좁게 적었다 —
  "지연 시간이 얼마야" 같은 정비 질문을 함께 끊으면 더 나쁘다
- 모델에게도 넘기지 않는다. 오늘 날짜를 모델이 답하면 그것은 지어낸 값이고
  화면에는 그럴듯하게 뜬다 (CLAUDE.md 3-3). **자유 모드에서도 같다** —
  자유 모드는 "근거 없이도 일반 지식을 달라" 이지 "없는 사실을 만들어
  달라" 가 아니다
- 끊는 것은 **도구가 알 수 없는 사실 질문**뿐이다. 노래·게임 같은 요청은
  그대로 모델이 사양한다 — 그쪽은 지어내도 사람이 속지 않는다

## 가드

`도구 목록 통합 [주입]` — 56번째 항목. 넷을 본다.

1. **규칙 ↔ 스키마 일치.** 각 도구의 설명·지시문·필드가 만들어진 지침에
   실렸는지, 그리고 **각 도구의 예시를 실제로 돌려** 그 도구로 가는지,
   규칙이 내는 type 을 모델이 고를 수 있는지
2. **주입 — 반쪽 등록 3종**(표현만 있음 / 스키마 설명 없음 / 안내문 없음)을
   넣으면 등록 점검이 죽는가. 진짜 목록은 넣었다 되돌리고 원상태를 대조한다
3. 새 도구 둘 — 탭 이동 4탭·이름 없을 때 되묻기·태그 무변경, 범위 밖 5종이
   `generic` 이 아니고(그래야 QA 로 안 내려간다) 실제 챗봇 호출에 **인용이
   붙지 않는가**. 경계로 "지연 시간이 얼마야" 를 잘못 끊지 않는지도 본다
4. **기존 챗봇 계열 18종 유지.** 규칙 계층을 통째로 갈아끼웠으므로 조회·
   원본·도면·판넬·사용법·공정 화면·후속 질문·인사·기능 안내·없는 태그가
   예전과 같은 판정을 내는지 표로 대조한다

가드가 고장을 잡는지도 확인했다. 등록 항목을 메모리에서만 망가뜨려 6종을
심었고 전부 실패로 걸렸다.

```
탭 이동 표현 제거            → navigate 예시가 chat 으로 갑니다
범위 밖 표현 제거            → '오늘 며칠이야' 가 generic (매뉴얼 검색으로 샙니다)
인터락 표현 제거            → 'XV-4101 인터락 조회' 가 diagnose 로 갑니다
스키마에서 정지 누락 (33 재현) → 스키마 줄에 stopScenario 필드가 없습니다
탭 이동을 스키마에서 감춤      → 규칙은 navigate 를 내는데 모델은 고를 수 없습니다
(시나리오 정지 가드에도 같은 주입) → LLM 명령 스키마에 stopScenario 가 없습니다
```

처음 조인 가드는 셋을 놓쳤다. 지침 전체를 한 덩어리로 놓고 낱말만 찾으니,
스키마에서 필드가 빠져도 설명문에 남은 같은 낱말이 가려 주었다. **스키마
줄과 설명을 따로** 보게 고쳤고, 기대하는 명령·필드 이름은 가드에 **따로**
적었다 — 목록에서 지울 때 가드도 함께 지워지면 그건 점검이 아니다.

## 측정

갈아끼운 것이 규칙 계층이므로, 문장 하나하나가 예전과 같은 판정을 내는지를
먼저 봤다. 대표 문장 79개 × 화면 상태 3가지 = 237건을 리팩터링 전후로 떠서
대조했다.

- **달라진 것 36건 = 의도한 12문장 × 3상태.** 나머지 201건 동일
- 자기 점검 **56항목 전건 통과** (모델 연결 2항목 포함 58행, 실패·주의 0)
- 매뉴얼 검색 45문항 **28/45 유지** — OX 패턴까지 같다
  `OOOOXOXOOOOXXOOXXOOOOOXOOXXXOOOXXOXXOOOOOOXXX`
- 홀드아웃 **2/10 유지** `XXXXXOXOXX`
- 인터락 **67/67** · 판넬·배선 **211/211**(변이 시험 3종 포함) · 조치 이력
  **100/100** 유지
- 실제 서버를 띄워 `/api/chat` 으로 탭 이동·범위 밖·알람 조회·시나리오

## 남는 것

- **화면 안의 간이 파서**(`ui/react/src/App.jsx` 의 `parseBotIntent`)는
  여전히 도구 지식을 따로 갖고 있다. 서버에 닿지 못할 때만 쓰이는 오프라인
  경로이고, 서버 목록을 읽어 오게 만들면 "서버가 없을 때 쓰는 것"이라는
  존재 이유와 어긋난다. 화면에도 "(오프라인 해석)" 이라고 표시된다. 합치지
  않기로 하고 여기 적어 둔다
- 챗봇 QA 경로가 로컬 7B 모델이 JSON 을 깨뜨릴 때 조용히 LLM 대화 경로로
  내려간다 (`except: pass`). 이번 변경과 무관한 기존 동작이지만, **폴백을
  탄 사실이 로그에도 화면에도 남지 않는다** — 결선 과제의 "폴백 표시"와
  같은 자리다
