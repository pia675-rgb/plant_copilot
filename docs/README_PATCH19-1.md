# 패치 19-1 — 조사가 붙은 태그를 놓치던 문제

패치 19 위에 덮으십시오.

```
api/server.py       find_tag 경계 수정 · 판넬 의도를 실행 목록에 추가 · 대체 금지
eval/selfcheck.py   태그 조사 표기 [주입] 항목 추가 (18 → 19)
run_claude.bat      줄바꿈 CRLF 복구 · 종료 코드 표시 후 pause
run_diag.bat        (신규) 서버를 띄우지 않고 단계별로 원인을 좁히는 진단
```

## 무엇이 잘못됐나

```
나:  ait-1001은 어느 위치에 있어?
봇:  AIT-4002 는 RIO-01 판넬입니다. 위치는 PROCESS AREA - EAST …
```

물어본 것과 **다른 설비**를 답했습니다. 두 가지가 겹쳤습니다.

### 1. ★ 한글 조사가 붙으면 태그를 통째로 놓쳤습니다

`find_tag` 가 경계를 `\b` 로 잡고 있었습니다.

```
"ait-1001은 어느 위치에 있어?"
        └ '1' 과 '은' 은 둘 다 단어 문자라 \b 가 경계로 보지 않습니다
```

정규식이 `ait-1001` 을 잡지 못하고, 못 잡으면 `find_tag` 는 **현재 화면에
선택된 태그로 조용히 대체**합니다. 그래서 AIT-4002 의 답이 나갔습니다.

경계를 영숫자 기준(`(?<![A-Za-z0-9])`)으로 바꿨습니다. 한글·공백·문장부호는
모두 구분자가 됩니다. 조사 `은/는/이/가/의/에서` 를 붙여도 읽습니다.

### 2. ★ 못 읽었을 때 다른 태그로 대신 답했습니다

경계를 고쳐도 남는 문제입니다. 리스트에 없는 태그를 물으면 여전히 현재
태그로 대체됩니다. "어디에 있어?" 는 **이름 자체가 질문의 주어**라서
대체가 성립하지 않습니다.

위치·고장 질의에서는 태그를 못 풀면 그 사실을 말합니다.

```
zzt-9999는 어느 위치에 있어?  →  ZZT-9999 는 계기 리스트에 없습니다.
```

### 3. 판넬 의도가 챗봇 실행 목록에서 빠져 있었습니다

`chat_help` 의 `ACTIONABLE` 에 `panel` 을 넣지 않아, 판넬 의도가 명령으로
실행되지 않고 매뉴얼 QA 경로로 흘렀습니다. 그래서 판넬 답 뒤에
"매뉴얼에서 근거를 찾지 못했습니다" 가 한 번 더 붙었습니다.

### 4. run_claude.bat 줄바꿈

패치 19 에서 파일을 편집하며 CRLF 가 LF 로 바뀌었습니다(47줄 중 36줄).
cmd 는 여러 줄 `if (...)` 블록에서 LF 를 만나면 파싱이 어긋납니다.
전 줄 CRLF 로 복구했고, 끝에 종료 코드 출력과 `pause` 를 넣어 창이
닫히지 않게 했습니다.

## 점검 항목 추가 (18 → 19)

```
태그 조사 표기 [주입]   조사 6종을 붙여도 태그를 읽는가
                       못 읽었을 때 현재 태그로 대신 답하지 않는가
```

[주입] 인 이유는, 이 고장이 **화면에 그럴듯한 답이 떠서 틀렸다는 사실
자체가 드러나지 않는** 종류이기 때문입니다. 검출 장치가 없으면 다시
들어옵니다.
