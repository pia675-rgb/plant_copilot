> **용어** — 「전체 세트」는 로컬 검증에만 사용한 공개 벤더 매뉴얼 42~45종 색인,

## 8/22 (토) — 저장소 정리와 배포 착수

**한 일** — 공개 저장소에서 로컬 전체 세트 파생물을 발견·제거하고 저장소 재생성. 클라우드 LLM 연결, 리랭커 효과 측정.

**막혔던 것** — API 429 오류를 크레딧 소진으로 오판했다가, 실제 원인은 요청 형식(헤더)임을 확인. 리랭커를 켜고 꺼도 점수가 완전히 동일했는데, 이때는 "효과 없음"으로 결론.

**배운 것** — `.gitignore`는 파일이 아니라 폴더 단위로 막아야 한다. 그리고 이날의 리랭커 결론은 이틀 뒤 틀린 것으로 밝혀진다(8/24).

## 8/23 (일) — DeepInfra 전환과 임베딩 비교

**한 일** — LLM 공급자를 DeepInfra로 전환. 임베딩 3종을 같은 45문항으로 비교 — 한글 동의어 유형이 8 → 3 → 1로 갈렸다.

**막혔던 것** — 배포용 상용 임베딩에서 한글 검색이 무너짐. 유형별로 나눠 재니 영문 문항은 세 구성이 동일 — 원인이 한↔영 구간에 있음이 분리됨.

**배운 것** — 모델 성능은 하나의 숫자가 아니다. 일반 벤치마크 우위가 특정 용도(교차 언어)에서는 뒤집힌다. 같은 다국어 모델(bge-m3)을 API로 제공하는 곳을 찾아 로컬과 배포를 같은 구성으로 맞췄다.

## 8/24 (월) — 이력 우선 규칙, 그리고 정정

**한 일** — 이력 우선 조치 규칙 완성(100문항 + 변이 시험). 4D 리포트가 화면과 다른 근거를 담던 결함 수정. 중복 근거 접기. 배포 구성 실측 — 로컬과 문항별 정오까지 동일.

**막혔던 것** — **8/22의 리랭커 측정이 틀렸음을 발견.** 설정은 갈렸지만 코드가 그 분기를 타지 않아 두 측정이 같았던 것. 실제로 재니 28→31로 효과가 있었다.

**배운 것** — 설정을 바꿨는데 결과가 완전히 같으면 "효과 없음"이 아니라 "적용 안 됨"을 먼저 의심한다. 결론은 정정하되 결정(리랭커 제외)은 유지 — 근거가 성능에서 비용(이미지 +2GB)으로 바뀌었을 뿐이다. 틀린 기록은 지우지 않고 정정 표시를 남겼다.

## 8/25 (화) — 홀드아웃이 평가셋의 편향을 드러냈다

**한 일** — 인터락 입력 기준 조회 수정(빈 응답 → 34건). 페이지 인용 정확도 68% → 100%(전수). 거절 시 모델 추측 기능(격리 설계). 검증 담당이 기존 문항을 보지 않고 만든 홀드아웃 10문항 채점.

**막혔던 것** — **홀드아웃 2/10.** 기존 45문항의 62%와 격차가 컸다. 원인을 한국어 문제로 추정했으나 영문 대조군도 2/10 — 갈린 것은 언어가 아니라 **원문 어휘를 얼마나 그대로 쓰는가**였다. 같은 날, 순위 개선용 청킹 가설(페이지 소제목)을 구현했으나 28→27, 홀드아웃 2→0으로 나빠져 전량 원복. 환경변수가 풀린 창에서 재구축을 돌려 데모 색인이 전체 세트로 덮이는 사고(세 번째)도 있었다.

**배운 것** — 작성자를 분리해야 평가셋의 편향 크기를 알 수 있다. 낮은 수치(2/10)는 고치지 않고 그대로 보고했다 — 실패 문항을 보고 조정하면 평가셋 맞춤이 된다. 가설이 그럴듯해도 측정 없이 채택하지 않는다는 원칙이 이번에는 채택 전에 작동했고, 기각한 시도에서 더 중요한 결함(페이지 인용 오차, 최대 17쪽)을 찾아 고쳤다.

## 8/26 (수) — 근거 수준 모드, 자료 반입 화면, 그리고 두 겹 잠금

**한 일** — 근거/자유 모드(추측은 어느 모드에서도 조치·리포트에 불포함). 배치 경로 고정 4종 — 세 번 반복된 색인 사고의 재발 방지. **자료 반입 화면**(기획서 확장 계획을 앞당김) — 본체는 파일 받기가 아니라 반입 직후 점검: 문서별 읽기·표준 24열 대조·매뉴얼↔기종 연결·태그 맞물림. 색인 재생성 진행 표시, 파일 관리(다운로드·2단계 삭제·`.prev` 보존). 배포 노출을 위해 편집 열쇠 + 동시 잠금(5분 임대) 추가, 배포에서 2기기 검증.

**막혔던 것** — 점검기를 고장 주입으로 시험하니(깨진 IO List, 기종 없는 매뉴얼) 사각이 드러났다 — "매뉴얼 없는 기종"은 잡는데 "기종 없는 매뉴얼"은 지나갔다. 역방향과 IO 카드 문서 분류를 추가. Windows에서 파일 삭제가 막혀 조사하니 **프로젝트 전체에서 워크북을 닫는 곳이 한 군데도 없었다** — 읽기만 하던 동안 잠복했다가 파일을 바꾸는 기능을 만들자 드러난 핸들 누수(8곳 수정). 재생성 중 도우미를 썼다가 GPU 경합으로 임베딩이 중단되는 것도 겪었다(안내문 반영).

**배운 것** — 리포트가 뜨는 것과 문제를 잡는 것은 다르다 — 점검기도 고장 주입으로 시험해야 한다. 재생성을 증분이 아닌 전체로 둔 것은 선택이다: **느린 것과 조용히 틀리는 것 중 느린 쪽을 골랐다.** 시험 후 색인을 원상 복구하고 재채점 — 28/45·2/10·67/67, 문항별 정오까지 동일. 잠금 시험 중 깨진 파일이 배포에 올라갔다가 `.prev` 되살리기로 복구됐다 — 당일 만든 보존 장치가 당일 실전 복구를 해냈다.

## 8/27 (목) — 알람이 매뉴얼에 없는 말을 한다

**한 일** — 챗봇 경계 5건. **「4D 기입란」 삭제**(도남진 제안 — 피드백 폼과 같은 항목을 두 번 적게 하고 있었다) 후 피드백 저장 값이 그대로 리포트 D3·D4로 가게 배선, 이력 통계. **패치 27** — SCADA 알람 어휘(HH·LL·LOOP ERROR·SSL 코드)가 매뉴얼에 **실측 0건**임을 확인하고, 카드 진단표 표제어로 잇는 알람 라우팅·SSL 16진 코드 조회·알람 폭주 역추적(카드→랙→판넬→PLC 4계층)을 넣었다. 데모 IO List 채널 중복 7건도 고쳤다.

**막혔던 것** — **네 번째 덮임 사고**: 홀드아웃 한국어판 파일이 영문 대조군 제작 중 영문으로 덮여 있었다(외부 검토가 발견). 8/25 스코어카드의 문항별 기록과 백업 초안을 대조해 복원, 재측정에서 2/10·통과 문항까지 동일 재현. 진단도 두 번 틀렸다(기기 필터 오진, 이미 측정으로 기각된 설정을 켜자고 함). 고친 것을 시험하다 **소문자 `loop error`가 라우팅을 비껴가** 충분성 1.00으로 엉뚱한 근거를 싣는 것을 발견 — 거절보다 나쁜, 확신에 찬 오답이었다. 자기 점검 16건 실패는 집 PC에 실물 자료가 없어 다른 자료를 읽은 탓이었다.

**배운 것** — 알람은 상태를 말하고 매뉴얼은 절차를 말한다. 문자열이 같아도 의미가 반대일 수 있고, 검색이 정상 동작해도 답이 어긋난다. 그리고 **첫 실사용 입력이 시험 스크립트가 못 잡은 것을 잡았다** — SCADA는 대문자로 보내지만 사람은 소문자로 친다. 재측정 28/45·2/10·67/67 유지, 수치가 오르지 않은 것도 설계대로다(평가셋에 없는 입력 경로를 고쳤으므로, 올랐다면 오염을 의심해야 한다).

## 8/28 (금) — 원칙을 고치고, 반나절을 오진했다

**한 일** — **패치 28: 에이전트 계층 1단계.** 8/26에 정한 "신규 기능 금지" 원칙을 수정하고(조건 4개를 걸었다 — 검색·판정 무접촉/가드 동반/전 지표 재측정/경위 기록), 기획서 확장 계획의 두 항목을 앞당겨 만들었다. **반입 수리 보조**(점검이 짚은 것을 수정안으로 제시하되 반영은 승인·열쇠·`.prev`를 거침)와 **동시 알람 조사**(공통 조상→반례→코드 근거→결론 6단계를 대신 밟고 단계를 전부 기록). SSL은 계기가 아니라 카드가 내는 신호여서 축이 맞지 않아 시연·설명서에서 뺐다.

**막혔던 것** — `selfcheck`가 **18건 실패**. 채널 중복·랙 겹침·인터락 62문항… 각기 다른 결함처럼 보였으나 **전부 한 원인**이었다. 환경변수 없이 돌려 기본 경로가 실물 트랙을 가리켰고, 폴백 한 줄이 v1 원본으로 조용히 갈아탔다. 더 나빴던 건 **경고가 안 뜬 것** — 가드가 폴백 뒤의 경로를 검사해 없는 폴더를 정상처럼 찍었다. 데모 트랙으로 다시 돌리니 전건 통과. 그 사이 세 가지를 "결함"으로 판단했다가 전부 철회했다.

**배운 것** — **문서로 막을 것과 코드로 막을 것은 다르다.** 이 함정은 인수인계에 이미 경고로 적혀 있었는데도 걸렸다. 색인 덮임은 배치 파일로 경로를 못 박아 재발이 끊겼지만, 점검에는 그런 배치가 없어 맨손으로 칠 수밖에 없는 구조였다. 그리고 원칙은 고칠 수 있다 — **고치는 것이 아니라 고친 것을 기록하지 않는 것이 문제다.** 조건 넷을 걸고 전부 재측정했고 수치는 하나도 움직이지 않았다. **바뀌지 않았음을 확인하는 것도 측정이다.**

## 이레를 관통한 것

숫자가 좋게 나오면 먼저 의심했고(만점 평가셋, 62%, 충분성 1.00의 오답), 예상과 다르면 측정 도구부터 봤다(리랭커, 페이지 대조, 자료 폴더). 틀린 결론·기각한 시도·우리가 낸 사고는 지우지 않고 정정 표시와 함께 남겼다. 검증할 수 없는 출력(모델 추측)은 품질을 주장하는 대신 자리를 제한했다.

현재 수치: 시연 색인(공개 매뉴얼 3종) 기준 45문항 28/45 · 홀드아웃 10문항 2/10(작성자 분리, 있는 그대로 보고) · 인터락 67/67 · 판넬 211/211 · 이력 100/100 · 페이지 인용 전수 정확. 배포와 로컬은 문항별 정오까지 동일.
