패치 19-6 위에 덮으십시오.

```

api/server.py                    /api/tag-consistency

```

## 세 문서는 TAG 로 서로를 가리킵니다

```
IO_LIST.xlsx          배선 — 이 태그가 어느 카드 어느 채널인가
INSTRUMENT_LIST.xlsx  사양 — 이 태그의 제조사·레인지·고장모드
DEMO_INTERLOCK_LIST   논리 — 이 태그가 어떤 인터락의 조건·출력인가
```

한쪽에서 태그를 고치고 다른 쪽을 안 고치면 조회가 조용히 빕니다. 화면에는
그럴듯한 답이 뜨고, 어긋났다는 사실 자체가 드러나지 않습니다.

**판정하지 않고 대조만 합니다.** 어느 쪽이 맞는지는 문서를 가진 사람이
정합니다. 이 모듈은 "두 문서가 다르다" 까지만 말합니다.

## 지적을 세 갈래로 나눕니다

고쳐야 할 곳이 다르기 때문입니다.

| 갈래 | 뜻 | 고칠 곳 |
|---|---|---|
| 누락 | 정규화해도 짝이 없다 | 문서 |
| 표기 불일치 | 정규화하면 같다 (AIT-1001 ↔ AIT1001) | 표기 통일 |
| 태그 형식 아님 | 접두어가 실재 태그와 다르다 | 파서 |

세 번째가 없으면 파서 오추출이 문서 누락으로 둔갑합니다. 실제로
`STAND-BY`, `DMF-RW-01A~I` 는 인터락 조건 문구에서 잘못 뽑힌 것이지
빠진 태그가 아닙니다.

> 접두어 목록을 IO List·계기 리스트에서만 뽑았더니 `P-2101A`·`XV-2102`
> 같은 **진짜 출력 태그가 '태그 형식 아님' 으로 둔갑**했습니다. 지금
> IO List 에 입력만 있어 P·XV 접두어가 없었기 때문입니다. 인터락 출력
> 태그도 접두어 원천에 넣어 고쳤습니다. 접두어 목록이 좁으면 진짜
> 누락이 파서 오류로 보입니다.

## 현재 데모 데이터 대조 결과 — 36건

```
IO List 76 · 계기 리스트 76 · 인터락 조건 41 · 인터락 출력 19

출력 태그 출처 불명   19건   XV-4101, P-1101A, UV-5102, LCV-01, RWP-01 …
조건 태그 출처 불명   15건   AIT-6004, FIT-5006, XV-2102, P-2101A …
태그 형식 아님         2건   STAND-BY, DMF-RW-01A~I
표기 불일치            0건
```

**이 36건은 대조기의 결함이 아니라 데이터의 상태입니다.** 그리고 원인이
하나로 모입니다.

### ★ 근본 원인 — IO List 에 입력(AI)만 있습니다

지금 IO List 76점은 전부 AI 입니다. 실물이라면 여기에

```
DO 점   XV-4101 개폐 출력, P-1101A 기동 출력 …
DI 점   XV-2102 개폐 확인 피드백, P-2101A 운전 상태 …
AO 점   LCV-01 밸브 개도 출력
```

이 함께 있어야 합니다. 그게 있으면 **36건 중 34건이 그대로 사라지고,
`DEMO_OUTPUT_LIST.xlsx` 라는 문서도 필요 없어집니다.** 지난 턴에
"output list 는 프로젝트에서 생기는 엑셀이 아니다" 라고 하신 것과 정확히
같은 지점입니다 — 출력은 별도 문서가 아니라 IO List 의 DO/AO 점입니다.

## selfcheck 27 → 28

```
태그 교차 정합성 [주입]   대조기가 살아 있는가
```

이 항목은 **지적 건수를 판정하지 않습니다.** 36건은 데이터의 문제이지
코드의 문제가 아니고, 건수로 통과/실패를 가르면 데이터를 고칠 때마다
점검이 깨집니다. 대신 태그 하나의 표기를 일부러 바꿔 넣어 '표기 불일치'
로 잡히는지 확인합니다.
