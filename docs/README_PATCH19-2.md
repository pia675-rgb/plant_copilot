## 전제가 틀렸습니다

패치 19 는 **판넬 상실**을 주 시나리오로 잡았습니다. 그런데 이 플랜트는
Siemens S7-400H/410H 이중화 구성이라 CPU·전원·통신이 이중화되어 있고,
**랙 증설도 스위칭으로 대응**합니다. 판넬 전체가 한 번에 죽는 상황은
계획 작업을 포함해도 성립하지 않습니다.

**단일인 것은 IO 카드 하나뿐입니다.** 그래서 판넬 상실 계산은 남겨 두지
않고 **삭제**했습니다. 성립하지 않는 시나리오에 숫자를 붙여 보여주면
그 숫자가 현장 판단의 근거로 쓰입니다. "계획 작업 기준" 같은 단서를
달아 남겨 두는 것도 같은 문제를 만듭니다.

판넬 조회 자체는 남습니다 — **위치·배치도·계기 구성** 조회 대상입니다.
상실 영향만 카드로 옮겼습니다.

## 카드 식별

`(판넬, 랙, 슬롯)` 입니다. 분산 IO 에서는 판넬이 곧 스테이션이라
랙·슬롯 번호가 판넬별로 매겨집니다.

```
CUB-B/R0/S8   AIT-1001, TIT-4004, TIT-4008        (3점)
CUB-A/R0/S1   AIT-2011, AIT-4005, PIT-3007, TIT-1012  (4점)
```

계기 72점이 **카드 33장**에 흩어져 있습니다.

```
CUB-B/R0/S8 카드를 잃으면
  계기 3점 상실 (PRETREATMENT 1 · UPW TANK 2)
  의존 인터락 1건 (안전 인터락 1건) · 영향 출력 1건
  ★ IL-1102-01 XV-1102 CLOSE — AIT-1001 상실, OR 결합이라 TIT-1004 경로 유지
  인터락 무관 2점 — 지시·기록만 상실
```

## ★ 공통원인 점검 — 카드로 옮긴 진짜 이유

카드가 단일 고장 지점이면, **OR 로 계기 여러 개를 걸어 두어도 그 계기들이
같은 카드에 물려 있으면 카드 하나로 중복 조건이 통째로 사라집니다.**
분산 배치 검토 항목이고, 리스트만으로 판정할 수 있습니다.

```
인터락 39건 점검 · 지적 0건
```

**0건은 '설계가 안전하다'가 아니라 '이 리스트 범위에서 걸린 것이 없다'는
뜻입니다.** 합성 데이터의 슬롯이 무작위 배정이라 충돌이 생기지 않았을
뿐입니다. 점검기가 실제로 붙잡는지는 주입으로 확인합니다.

```
IL-4101-01 의 조건 태그 두 개를 같은 카드로 옮김 → 검출됨 (보호 전부 상실)
```

## 챗봇

```
ait-1001 카드가 죽으면?      → CUB-B/R0/S8, 같은 카드 3점, 의존 인터락과 영향 출력
AIT-1001은 어느 위치에 있어?  → 판넬·그리드·단자대·슬롯/채널·카드 ID
같은 카드에 몰린 인터락 있어?  → 공통원인 점검 결과
CUB-B 내리면 뭐가 죽어?       → "이중화 구성이라 판넬 전체가 한 번에 죽는 상황은
                                다루지 않습니다. 단일 고장 단위는 IO 카드이고…"
```

마지막 항목이 중요합니다. 질문을 거절하지 않고 **왜 성립하지 않는지 말한
뒤 카드로 되돌립니다.**


마지막 항목은 **되살아나기 쉬운 기능을 잠그는** 용도입니다. 편의상 다시
넣기 쉬운데, 그러면 없는 시나리오가 조용히 화면에 돌아옵니다.

`트립 단정 금지` 항목은 카드 서술 기준으로 바꿨습니다.

## 남은 확인 사항

합성 계기 리스트의 슬롯이 무작위 배정이라 카드당 1~5점이고 공통원인
지적이 0건입니다. 실물은 카드당 8~16채널이고 같은 루프의 계기가 인접
슬롯에 몰리는 경향이 있어 결과가 달라집니다. 데모에서 지적 사례를
보이려면 슬롯 배정을 실제 결선 관행에 맞게 다시 만들어야 하는데, 그건
**의도적으로 심는 것**이므로 그렇게 한다면 심었다는 사실을 스코어카드에
밝혀야 합니다.
