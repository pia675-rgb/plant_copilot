# 패치 4 — 인터락 평가셋 + 확장 문항 템플릿

`eval/` 폴더에 파일 5개를 추가합니다. 기존 파일은 건드리지 않습니다.

```
eval/make_eval_interlock.py         인터락 평가셋 생성기
eval/run_eval_interlock.py          채점기 + 스코어카드
eval/eval_set_interlock.json        생성된 72문항
eval/scorecard_interlock.md         결과 (72/72)
eval/eval_set_holdout_TEMPLATE.json 검증 담당용 확장 문항 템플릿
```

## 왜 필요했나

기획서에서 인터락을 핵심 자산으로 내세우는데 **그쪽 숫자가 하나도
없었습니다.** 검색은 45문항으로 재는데 인터락·도면·이력은 아무도
재지 않고 있었습니다.

## 성격이 다릅니다

인터락 조회는 **검색이 아니라 조회**입니다. 정답이 리스트에 확정적으로
존재하므로 만점이 기본값이고, 점수가 낮다는 것은 "성능이 부족한" 것이
아니라 **로직이 틀렸다**는 뜻입니다.

그래서 이 평가의 값어치는 높은 점수 자체가 아니라 **회귀 방지**에
있습니다. 실물 인터락 리스트로 교체할 때 컬럼 구조가 달라지면 여기서
먼저 깨집니다.

## 정답을 어디서 가져왔나

`ingest.interlock.load_interlocks()` 가 돌려주는 **원천 레코드에서 직접
계산**했습니다. 조회 엔진(`InterlockIndex`)의 출력을 정답으로 삼으면
엔진이 틀려도 100%가 나오므로, 두 경로가 독립이어야 시험이 성립합니다.

## 문항 구성 (72문항)

| 유형 | 문항 | 무엇을 보는가 |
|---|---|---|
| layer | 32 | 동작을 막는 조건과 허가하는 조건이 섞이지 않는가 |
| reverse | 12 | 입력 태그가 어느 출력에 영향을 주는가 |
| attr | 12 | 바이패스 가부·리셋 방식이 정확한가 |
| value | 10 | 설정치·단위·지연이 원문과 일치하는가 |
| absent | 5 | 리스트에 없는 태그를 지어내지 않는가 |
| unparsed | 1 | 못 읽은 조건의 원문이 보존되는가 |

현재 결과는 **72/72** 입니다.

## 이 평가가 허수가 아님을 확인했습니다

만점짜리 평가는 아무것도 안 지킬 수 있습니다. 그래서 일부러 로직을
깨뜨려 잡히는지 확인했습니다.

| 고의 변이 | 결과 |
|---|---|
| 층 분리 제거 (모든 항목을 '막음'으로) | layer **0/32**, 전체 40/72 |
| 없는 태그에 빈 결과 반환 | absent **0/5**, 전체 67/72 |
| 원복 | 72/72 |

기획서에 적은 두 원칙 — 층을 나눈다, 없는 것을 지어내지 않는다 —
각각에 대응하는 문항이 실제로 그 원칙을 지키고 있습니다.

## 실행

```cmd
python -m eval.make_eval_interlock
python -m eval.run_eval_interlock --md eval/scorecard_interlock.md
```

인터락 리스트를 바꾸면 생성기를 다시 돌려 평가셋을 갱신하십시오.
합성 리스트 39건 기준이며, 실물로 교체하면 문항 수가 달라집니다.

# 확장 문항 템플릿 (eval_set_holdout_TEMPLATE.json)

검색 평가셋 45문항의 일반화를 확인하려면 **개발자가 만들지 않은
문항**이 필요합니다. 제가 직접 작성하지 않은 이유는 같은 편향이
들어가기 때문입니다. 제가 임베딩이 잘 잡을 법한 한국어 표현을
무의식적으로 고르게 됩니다.

템플릿에 작성 규칙과 기대값 찾는 명령을 넣어 두었습니다. 핵심은
다섯 가지입니다.

1. `eval_set_v2.json` 을 열어보지 말 것 — 기존 표현을 따라가게 된다
2. 매뉴얼 PDF 를 보고 만들 것 — 시스템에 먼저 물어보지 말 것
3. 현장 정비원이 쓸 법한 한국어로 쓸 것 — 영문 용어를 떠올리지 말 것
4. **한 번만 채점하고 결과를 보고 문항을 고치지 말 것**
5. 근거 없는 문항(abstain)을 반드시 섞을 것

작성 후:

```cmd
python -m eval.run_eval_v2 --eval eval/eval_set_holdout.json --systems hybrid --md eval/scorecard_holdout.md
```

여기서 45문항과 같은 경향(syn·body 가 lexical 대비 크게 높음)이
나오면 33/45 가 실력이고, 안 나오면 45문항에 맞춰져 있었다는 뜻입니다.
어느 쪽이든 그 결과를 기획서에 적는 것이 맞습니다.
