# PATCH 32 — 검사가 실패를 보고서 통과시켰다

2026-09-02 · 하네스 점검(교육 4회차 개념) 적용

## 발견

`run_check_demo.bat` 을 처음 돌린 자리에서 드러났다.

```
[실패] 자료 폴더    demo_data — 없음: 인터락 리스트(interlock)
[실패] 임베딩 호출  연결할 수 없습니다
실패 2건 — 이 상태로 평가를 돌리면 ...
```

그런데 **배치가 멈추지 않고 selfcheck 로 넘어갔다.** 그리고 그 selfcheck
는 인터락 67/67 로 통과했다. 두 가지가 동시에 이상했다.

## 원인 둘

**① 인터락 자료 판정이 폴더를 몰랐다.**

`config.INTERLOCK_XLSX` 는 **파일일 수도 폴더일 수도 있다.** 실물 인터락
리스트는 여러 엑셀로 나뉘어 오므로 폴더를 통째로 가리키게 설계했다
(`_resolve_interlock_xlsx`). 그런데 preflight 는 `os.path.isfile` 만 봤다.

자료는 멀쩡한데 "없음" 이라고 보고했고, 같은 자료로 인터락 조회는 67/67 을
냈다. **점검이 틀렸는데 자료를 탓하고 있었다.**

**② 실패해도 종료 코드가 0 이었다.**

```python
return 1 if (bad and args.strict) else 0
```

`--strict` 를 붙였을 때만 1 을 냈다. 배치의 `if errorlevel 1` 이 걸릴 리
없었다. **검사가 실패를 화면에 찍고서 통과시키는 것은 검사가 없는 것보다
나쁘다** — 봤다고 착각하게 만든다.

## 무엇을

- `eval/preflight.py`
  - `_interlock_exists()` — 파일이면 파일, 폴더면 그 안의 xlsx/xlsm 유무로
    판정. `c_data_dir` 과 `c_interlock` 이 함께 쓴다
  - 실패가 있으면 **기본으로 종료 코드 1**. 예전처럼 진행하려면
    `--lenient` (`--strict` 는 호환용으로 남김)
- `run_check_demo.bat` (신설) — 데모 트랙 전용 점검 배치. 환경변수를 못
  박고, 자료·색인 가드를 두고, preflight 를 거쳐 selfcheck 로 간다
- `CLAUDE.md` (신설) — 여러 문서에 흩어져 있던 규칙을 한곳에
- `.claude/agents/` (신설) — 문서 정합·수치 감사·결선 우선순위 역할 파일
- `eval/selfcheck.py` — `환경 점검 게이트 [주입]` 가드. 없는 자료 폴더를
  가리켜 실패 상황을 만든 뒤 **종료 코드가 실제로 1 인지** 확인하고,
  `--lenient` 는 0 인지도 본다

## 측정

- 신규 가드 통과. selfcheck 54항목 전건
- lexical 45문항 **16/45 유지**
- preflight: 정상 자료에서 `자료 폴더 OK` · `인터락 리스트 37건 / 조건
  103개`, 실패 상황에서 종료 코드 1

## 왜 이것을 고쳤나

교육 자료의 하네스 개념 — 같은 규칙도 **말(약함) → 문서(중간) →
코드(강함)** 중 어디에 두느냐로 강제력이 달라진다 — 에 비추면, 이
프로젝트에서 아직 "약함" 에 남아 있던 자리가 두 곳이었다.

1. 점검 실행 경로 (손으로 환경변수를 쳐야 함) → `run_check_demo.bat` 신설
2. 점검 실패의 강제력 (표시만 하고 통과) → 종료 코드로 고정

문서에 경고를 적어 두는 것으로는 막히지 않는다는 것을 세 번 겪고 나서
코드로 옮겼다.

## 추기 — 가드가 잡아낸 세 번째 결함 (같은 날)

사용자 PC 에서 `환경 점검 게이트 [주입]` 가드가 실패했다.

```
[실패] 환경 점검 게이트 [주입]   --lenient 인데 종료 코드 1
```

**게이트 로직은 맞았다. 죽은 이유가 달랐다.**

preflight 의 메시지에 cp949 에 없는 글자(em dash)가 있다. 콘솔에서는
멀쩡한데, **출력을 파이프나 파일로 받는 순간** 윈도우가 인코딩을 cp949 로
잡아 `UnicodeEncodeError` 로 죽는다. 그 죽음이 종료 코드 1 로 나타나
**게이트가 동작한 것처럼 보이기까지 했다.**

- 콘솔에서만 돌리면 평생 안 보인다
- `run_check_demo.bat > log.txt` 로 받으면 그때부터 죽는다
- 죽은 것을 게이트가 막은 것으로 오해할 수 있다

조용히 틀리는 쪽이라 고쳤다.

- `eval/preflight.py` — 시작할 때 stdout·stderr 를 utf-8 로 고정
  (`reconfigure(encoding="utf-8", errors="replace")`)
- `eval/selfcheck.py` — 가드가 자식 프로세스에 `PYTHONIOENCODING=utf-8` 을
  주고, **stderr 에 Traceback 이 있으면 별도로 보고**한다. 예외로 죽은
  것과 게이트가 막은 것을 구분하지 못하면 가드가 거짓 통과를 낸다

**가드를 만들자마자 그 가드가 결함을 하나 더 찾았다.** 검사가 무엇을
보는지 정하면, 보기로 한 것 바깥에 있던 문제가 드러난다.
