## 추기 — 가드가 잡아낸 세 번째 결함 (같은 날)

사용자 PC 에서 `환경 점검 게이트 [주입]` 가드가 실패했다.

```
[실패] 환경 점검 게이트 [주입]   --lenient 인데 종료 코드 1
```

**게이트 로직은 맞았다. 죽은 이유가 달랐다.**

preflight 의 메시지에 cp949 에 없는 글자(em dash)가 있다. 콘솔에서는
멀쩡한데, **출력을 파이프나 파일로 받는 순간** 윈도우가 인코딩을 cp949 로
잡아 `UnicodeEncodeError` 로 죽는다. 그 죽음이 종료 코드 1 로 나타나
**게이트가 동작한 것처럼 보이기까지 했다.**

- 콘솔에서만 돌리면 평생 안 보인다
- `run_check_demo.bat > log.txt` 로 받으면 그때부터 죽는다
- 죽은 것을 게이트가 막은 것으로 오해할 수 있다

조용히 틀리는 쪽이라 고쳤다.

- `eval/preflight.py` — 시작할 때 stdout·stderr 를 utf-8 로 고정
  (`reconfigure(encoding="utf-8", errors="replace")`)
- `eval/selfcheck.py` — 가드가 자식 프로세스에 `PYTHONIOENCODING=utf-8` 을
  주고, **stderr 에 Traceback 이 있으면 별도로 보고**한다. 예외로 죽은
  것과 게이트가 막은 것을 구분하지 못하면 가드가 거짓 통과를 낸다

**가드를 만들자마자 그 가드가 결함을 하나 더 찾았다.** 검사가 무엇을
보는지 정하면, 보기로 한 것 바깥에 있던 문제가 드러난다.
