# PATCH 32 — 검사가 실패를 보고서 통과시켰다

2026-09-02 · 하네스 점검(교육 3회차 개념) 적용

## 발견

`run_check_demo.bat` 을 처음 돌린 자리에서 드러났다.

```
[실패] 자료 폴더    demo_data — 없음: 인터락 리스트(interlock)
[실패] 임베딩 호출  연결할 수 없습니다
실패 2건 — 이 상태로 평가를 돌리면 ...
```

그런데 **배치가 멈추지 않고 selfcheck 로 넘어갔다.** 그리고 그 selfcheck
는 인터락 67/67 로 통과했다. 두 가지가 동시에 이상했다.

## 원인 둘

**① 인터락 자료 판정이 폴더를 몰랐다.**

`config.INTERLOCK_XLSX` 는 **파일일 수도 폴더일 수도 있다.** 실물 인터락
리스트는 여러 엑셀로 나뉘어 오므로 폴더를 통째로 가리키게 설계했다
(`_resolve_interlock_xlsx`). 그런데 preflight 는 `os.path.isfile` 만 봤다.

자료는 멀쩡한데 "없음" 이라고 보고했고, 같은 자료로 인터락 조회는 67/67 을
냈다. **점검이 틀렸는데 자료를 탓하고 있었다.**

**② 실패해도 종료 코드가 0 이었다.**

```python
return 1 if (bad and args.strict) else 0
```

`--strict` 를 붙였을 때만 1 을 냈다. 배치의 `if errorlevel 1` 이 걸릴 리
없었다. **검사가 실패를 화면에 찍고서 통과시키는 것은 검사가 없는 것보다
나쁘다** — 봤다고 착각하게 만든다.

## 무엇을

- `eval/preflight.py`
  - `_interlock_exists()` — 파일이면 파일, 폴더면 그 안의 xlsx/xlsm 유무로
    판정. `c_data_dir` 과 `c_interlock` 이 함께 쓴다
  - 실패가 있으면 **기본으로 종료 코드 1**. 예전처럼 진행하려면
    `--lenient` (`--strict` 는 호환용으로 남김)
- `run_check_demo.bat` — preflight 앞에 주석 세 줄. Ollama 가 꺼져 있으면
  임베딩 확인에서 오래 기다린다는 것(멈춘 것이 아님)을 적었다
- `eval/selfcheck.py` — `환경 점검 게이트 [주입]` 가드. 없는 자료 폴더를
  가리켜 실패 상황을 만든 뒤 **종료 코드가 실제로 1 인지** 확인하고,
  `--lenient` 는 0 인지도 본다. 인터락 폴더 인식도 함께

## 왜 이것을 고쳤나

교육 자료의 하네스 개념 — 같은 규칙도 **말(약함) → 문서(중간) → 코드(강함)**
중 어디에 두느냐로 강제력이 달라진다 — 에 비추면, 이 프로젝트에서 아직
"약함" 에 남아 있던 자리가 두 곳이었다.

1. 점검 실행 경로 (손으로 환경변수를 쳐야 함) → `run_check_demo.bat` 신설
2. 점검 실패의 강제력 (표시만 하고 통과) → 종료 코드로 고정

문서에 경고를 적어 두는 것으로는 막히지 않는다는 것을 세 번 겪고 나서
코드로 옮겼다.
