# 패치 12 — 대화형 응답

패치 11 위에 덮으십시오. 패치 7~11 내용을 모두 포함합니다.

## 무엇이 문제였나

```
사용자: 너는 어떤 기능이 있니?
챗봇:   예) AIT-4002 low acid 알람 조회해줘 / XV-4101 인터락 조회 / 사용법
```

패치 11에서 규칙 우선으로 바꾸면서 제가 과하게 만들었습니다. 규칙이
못 알아들으면 LLM 에 물어보긴 하는데, **LLM 의 답을 규칙의 상투적인
예시 문구로 덮어쓰고** 있었습니다.

## 고친 것

### 1. 포괄 응답과 구체적 안내를 구분

규칙 엔진의 `type=chat` 응답에는 두 종류가 있습니다.

| 종류 | 예 | 처리 |
|---|---|---|
| 구체적 안내 | "ZZZ-99 는 리스트에 없습니다" / "태그를 알려주세요" | **규칙 우선** |
| 포괄 응답 | "예) AIT-4002 ... / XV-4101 ..." | LLM 답을 살림 |

포괄 응답은 "아무것도 못 알아들었다"는 뜻이므로 `generic` 표식을 달아
LLM 답을 덮지 않게 했습니다.

### 2. LLM 에게 앱 기능을 알려줌

이전 시스템 프롬프트는 "메시지를 명령 JSON 으로 파싱하라"만 지시했고,
이 앱이 무엇을 하는 도구인지 알려주지 않았습니다. 그래서 기능을 물어도
답할 재료가 없었습니다.

알람 조회·근거 부재 시 거절·보수 이력 대조·인터락 층별 조회·도면·
4D 리포트를 프롬프트에 넣고, **명령이 아니라 질문이나 인사이면
자연스럽게 답하되 바로 써 볼 예시를 한 줄 덧붙이도록** 지시했습니다.

## 확인 결과

| 입력 | 경로 | 결과 |
|---|---|---|
| `너는 어떤 기능이 있니?` | llm | 기능 설명 |
| `안녕` | llm | 대화형 응답 |
| `LCV-01 인터락 조회해줘` | rule | 인터락 실행 |
| `사용법` | rule | 가이드 |
| `ZZZ-99 인터락 조회` | rule 문구 유지 | 없는 태그 안내 |
| `인터락 조회` | rule 문구 유지 | 태그를 되물음 |

selfcheck 의 `챗봇 명령 실행 [주입]` 이 양방향을 봅니다 — LLM 이
망가져도 명령이 실행되는지, 그리고 규칙이 대화형 답변을 덮지 않는지.

## 대화 품질은 모델에 달려 있습니다

qwen2.5:7b 의 한국어 생성 품질은 높지 않습니다. MAXIS 같은 매끄러운
대화를 기대하시면 모델을 바꾸는 편이 낫습니다.

```cmd
ollama pull exaone3.5:7.8b
set COPILOT_MODEL=exaone3.5:7.8b
```

한국어 특화 모델(LG AI연구원)이라 같은 프롬프트에서 문장 품질이
확실히 낫습니다. 사내 Azure OpenAI 키가 나오면 그쪽이 품질·속도 모두
가장 좋습니다.

**다만 시연 관점에서는 대화 품질이 핵심이 아닙니다.** 심사에서 보는
것은 근거 있는 조치와 인터락 조회이고, 챗봇은 그 기능으로 가는
입구입니다. 규칙 우선 구조 덕분에 명령 실행은 모델 품질과 무관하게
동작하므로, 대화 문장이 다소 어색해도 시연은 안전합니다.
