## 2. 검증에 쓴 데이터

### 2-1. 전부 합성입니다

**사내 원본 데이터는 한 건도 포함되어 있지 않습니다.** 제출물의 모든 자료는
실제 설비 문서의 **구조와 난이도를 본떠 새로 만든 것**입니다.

| 자료 | 규모 | 만든 방식 |
| --- | --- | --- |
| IO List | 100점 · 표준 24열 | 실제 프로젝트 IO List의 열 구성을 그대로 따르고 값은 새로 생성 |
| 계기 리스트 | 100행 · 16항목 | 실물 양식(SENSOR TYPE, MODEL, RANGE 등) |
| TB List | 100점 · 판넬 6 · TB 블록 36 | mastertool 격자 양식 |
| 인터락 리스트 | 출력 100개 · Fail 표기 18건 · 조건 34 | 실물 양식(층·AND/OR·지연·래치) |
| 도면 | P&ID · 배치도 · 외형도 · 결선도 4종 | 태그가 실제로 찍힌 PDF를 생성 |
| 보수 이력 | 29건 · 19태그 | 증상·실제 원인·조치·소요 시간·매뉴얼 일치 여부 |
| 벤더 매뉴얼 | 3종 | **제조사가 공개 배포하는 실제 문서** (출처 명기) |
| 색인 | 1,210 청크 · 코드표 306건 | 위 매뉴얼에서 추출 |
| 판넬 구성 | 판넬 6 · 카드 36 | IO List에서 파생 |

### 2-2. 얼마나 실제와 유사한가

의도적으로 맞춘 것은 **양이 아니라 난이도**입니다.

- **양식** — 열 이름·표기 방식을 실물에서 가져왔습니다. 인터락 조건이 행마다
  하나씩(OR) 나열되는 방식, 카드 위치를 `D03-S01`로 적는 방식처럼 파서가
  실제로 부딪히는 형태를 그대로 두었습니다.
- **불완전함** — 값이 비어 있는 칸을 일부러 남겼습니다. 단자 번호가 없는
  채널 24점은 지어내지 않고 비워 두었고, 화면은 그 자리를 "미상"으로
  표시합니다. 실물 자료는 언제나 이렇게 옵니다.
- **매뉴얼이 없는 기종** — 계기 중 일부는 벤더 매뉴얼이 없습니다. 그 태그를
  물으면 도구가 거절해야 하며, 실제로 거절합니다(3-4절).
- **매뉴얼과 다른 이력** — 이력 29건 중 일부는 매뉴얼이 지목한 원인과
  실제 원인이 **달랐던** 기록입니다(불일치·부분일치). 매뉴얼만 믿으면 안
  된다는 상황을 재현하기 위해 넣었습니다.

**맞추지 못한 것**: 실물 프로젝트의 IO List는 2,432행 규모입니다. 여기서는
100점으로 줄였습니다. 규모가 검색 순위에 미치는 영향은 3-5절에 적었습니다.

### 2-3. 검증 색인과 제출 색인이 다릅니다

로컬 검증에는 공개 벤더 매뉴얼 42~45종을 색인한 「**전체 세트**」를 썼고,
제출물에는 3종만 실은 「**데모 세트**」를 실었습니다. 두 세트 모두 사내
원본이 아니지만, **42종의 목록 조합이 실제 프로젝트의 설비 구성을 드러내기
때문에** 전체 세트는 외부로 내보내지 않았습니다.

이 원칙을 지킨 비용이 수치로 나타납니다.

| | 전체 세트(로컬) | 데모 세트(제출) |
| --- | --- | --- |
| 매뉴얼 | 42종 | 3종 |
| 청크 | 650 | 1,210 |
| 45문항 | 33/45 | 28/45 |

문서 수는 줄었는데 청크는 늘었습니다. 3종을 촘촘히 청킹하면서 같은 문서
안에서 비슷한 후보가 다수 만들어졌고, 정답이 상위 3건 밖으로 밀립니다.
**본 문서의 모든 수치는 데모 세트 기준**입니다.

### 3-2. 검색 구성을 바꿨을 때

같은 색인·같은 평가셋에서 검색 방식만 바꿔 측정했습니다.

| 구성 | 전체 | code | syn | en | body | typo |
| --- | --- | --- | --- | --- | --- | --- |
| lexical (어휘만) | 16/45 | 4/4 | 0/14 | 4/5 | 0/9 | 0/4 |
| **hybrid (배포 구성)** | **28/45** | 4/4 | 8/14 | 4/5 | 5/9 | 1/4 |
| full (재정렬 포함) | 31/45 | 4/4 | 9/14 | 5/5 | 5/9 | 2/4 |

재정렬이 3문항 이득이지만 **배포 구성에서는 제외**했습니다. 컨테이너
이미지에 딥러닝 프레임워크 약 2GB가 포함되어 호스팅 요건이 크게 올라가기
때문이며, 성능이 아니라 비용에 근거한 판단입니다. 얻는 것과 드는 것을
비교해 제외했고 코드에는 경로를 남겨 두었습니다.

### 3-3. 임베딩 모델을 바꿨을 때

배포용으로 상용 임베딩을 검토하다 **한국어 검색이 무너지는 것**을
발견했습니다. 유형별로 나눠 재니 원인이 분리됐습니다.

| | 한국어 동의어(syn 14문항) | 영문(en 5문항) |
| --- | --- | --- |
| 다국어 모델(bge-m3) | 8 | 4/5 |
| 상용 A | 3 | 4/5 |
| 상용 B | 1 | 4/5 |

영문은 세 구성이 동일하고 한국어만 갈렸습니다. **일반 성능이 좋은 모델이
교차 언어 용도에서는 뒤집힐 수 있다**는 것이 이 측정의 결론이며, 같은
다국어 모델을 API로 제공하는 곳을 찾아 로컬과 배포를 같은 구성으로
맞췄습니다.

### 3-5. 자료가 어긋났을 때 (고장 주입)

정상 자료로만 시험하면 점검기가 동작하는지 알 수 없어, **일부러 망가뜨린
자료를 넣어** 잡아내는지 확인했습니다.

| 주입한 고장 | 결과 |
| --- | --- |
| IO List의 열을 깨뜨림 | 24개 검사 중 23개 경고, 판넬 조회 실제 고장과 일치 → 이전 판으로 복구 |
| 기종이 없는 매뉴얼을 넣음 | 초기에는 **통과해 버림** → 역방향 검사 추가 후 검출 |
| 이력 번호를 위조 | 100문항 중 해당 4문항만 검출(나머지는 영향 없음) |
| 존재하지 않는 근거를 조치에 삽입 | 인용 검증에서 차단 |
| 다른 모델로 구운 임베딩 캐시 | 서명 대조로 거부 |
| 같은 카드·같은 채널에 두 태그 배정 | 채널 유일성 검사에서 검출(7건) → 재배정 |

**"기종이 없는 매뉴얼"은 처음에 통과했습니다.** 점검기도 고장 주입으로
시험해야 사각이 드러난다는 것을 이 건에서 배웠습니다.

자료 정합성·PDF 폰트까지 54항목이며, **현재 전건 통과**입니다.

## 4. 잘 되지 않은 조건

감추지 않고 적습니다. 아래는 모두 **측정으로 확인된** 한계입니다.

### 4-1. 작성자를 분리한 문항에서 20%

개발에 관여하지 않은 팀원이 기존 45문항을 **열어보지 않고** 10문항을
만들었습니다. 결과 **2/10**입니다. 기존 평가셋의 62%와 격차가 큽니다.

원인을 한국어 문제로 추정했으나, 같은 내용을 영문으로 만든 대조군도
2/10이었습니다(유형별 분포 동일, 통과 문항은 한국어 H06·H08 / 영문
H07·H08로 상이). 갈린 것은 언어가 아니라 **질의가 매뉴얼 원문의 어휘를
얼마나 그대로 쓰는가**였습니다. 매뉴얼이 `container`라고 쓴 것을 "통"이나
`bottle`로 바꿔 말하면 한국어로도 영어로도 도달하지 못합니다.

이 대조군에는 기록해 둘 사고가 있습니다. 영문판을 만들며 한국어판 파일이
영문 내용으로 **덮였고**, 외부 코드 검토가 이를 발견했습니다. 한국어 측정
기록(8/25 스코어카드, 실패 8건의 문항·점수)과 백업의 초안 파일을 대조해
복원했으며, 8/27 재측정에서 같은 결과가 재현되었습니다 — 총점 2/10에
통과 문항(H06·H08)까지 동일합니다. 본 문서의 홀드아웃 수치는 복원 후
재측정 값입니다.

**이 수치를 고치지 않았습니다.** 실패 문항을 보고 조정하면 그 평가셋도
맞춤이 되기 때문입니다. 낮은 값을 그대로 보고합니다.

### 4-2. 문서 범위 밖 질의를 거절하지 못함

45문항의 거절 문항은 "장비에서 커피 냄새가 납니다"처럼 설비와 명백히
무관한 것이라 3/6을 맞혔습니다. 그러나 홀드아웃의 거절 문항 3건(냉각팬 교체
주기, 샘플 온도 자동 정지 설정, 배터리 백업 전원)은 **설비와 관련은 있으나
매뉴얼에 없는 내용**이고, **0/3**입니다.

후자가 현장에서 실제로 나올 질문입니다. 임계값을 올리면 이 3문항을 얻지만
정답 문항을 잃습니다. 조정하지 않았습니다.

### 4-3. 오타에 약함

4문항 중 1문항만 맞힙니다(재정렬 포함 구성은 2문항). 문자 단위 정규화
계층으로 다룰 문제로 보며 이번 범위에서는 다루지 않았습니다.

### 4-4. SCADA 알람 어휘가 매뉴얼에 없음

색인을 전수 검색한 결과입니다.

```
loop error   0건
high high    0건
low low      0건
```

매뉴얼은 벤더가 쓰고 알람명은 SCADA 엔지니어가 씁니다. 접점이 없는 것이
정상입니다. 문자열이 우연히 겹칠 때는 더 나쁩니다 — `power off`로 검색하면
장비를 *끄는 절차* 문서가 원인 근거로 올라옵니다. 알람은 장비가 *꺼져
있다는 상태*를 말하는데 말입니다.

알람명이 유한하므로 카드 진단표·트러블슈팅 장의 실제 표제어로 잇는 규칙을
넣었고, **평가 448문항에서 이 규칙이 한 번도 발화하지 않음**을 자기 점검으로
상시 감시합니다. 규칙이 평가 점수를 몰래 움직이지 않는다는 것을 측정으로
지키기 위해서입니다. 적용 후 재측정에서 45문항 28/45 · 홀드아웃 2/10 ·
인터락 67/67로 변동이 없었습니다.

다만 이 방식은 **알람명이 유한하고 열거 가능할 때만** 성립합니다.

### 4-5. 배치도의 단자 표기가 조회 결과와 다릅니다

**같은 계기를 두 문서가 다른 번호로 가리킵니다.**

| | `TIT-1012` 의 단자 |
| --- | --- |
| 배선 자료 (조회 화면·챗봇) | `IW568+` |
| 배치도 (도면) | `TB4-19` |

단자 번호를 PLC 주소 체계로 다시 붙이면서(패치 30) 배치도가 갱신되지
않았습니다. 조회 결과를 들고 도면에서 찾으면 그 번호가 없습니다.

**조회 결과 자체는 일관됩니다** — 배선 자료·판넬 조회·챗봇 역조회가 모두
같은 값을 냅니다. 어긋난 것은 도면 한 곳이며, 도면 생성기를 재정비된
번호에 맞춰 다시 만들어야 합니다. 판넬 평가셋 재측정이 따르므로 마감
기간에는 착수하지 않고 확장 과제로 둡니다.

**09-02 리허설에서 발견했습니다.** 검색·조회 평가로는 드러나지 않는
종류입니다 — 두 산출물을 나란히 놓고 봐야 보입니다.

### 4-6. 시도했다가 버린 것

매뉴얼 책갈피에 없는 페이지 내 소제목을 찾아 청크 제목에 덧붙이는 방식을
구현했습니다. 고유 제목이 403→499개로 늘어 의도한 대로 변별력은 올랐으나,
**45문항 28→27, 홀드아웃 2→0**으로 점수가 내려가 전량 원복했습니다.

코드표는 한 글자도 바뀌지 않았는데 코드표 문항이 떨어진 것으로 보아, 길고
다양해진 본문 제목이 코드표 항목을 순위에서 밀어낸 것입니다.

이 시도에서 별개 결함을 찾았습니다 — 근거 인용의 페이지 번호가 근사값이라
**세 건 중 한 건이 실제 페이지와 어긋나 있었습니다**(최대 17쪽). 청크
앞부분을 페이지 본문과 대조하도록 고쳐 전수 정확해졌습니다.

### 4-7. 시험되지 않은 것

이력 규칙의 기종 가드는 현재 자료로 검증되지 않습니다. 이력에 "기종이
다른데 증상이 비슷한" 쌍이 없어, 기종 조건을 코드에서 빼도 문항이 하나도
무너지지 않습니다. 합성 픽스처로 규칙 자체는 확인했으나, 실제 자료에서 이
조건이 필요한 상황이 생기는지는 이력이 더 쌓여야 알 수 있습니다.

## 6. 재현 절차

```
1. 압축을 풀고 프로젝트 폴더로 이동
2. pip install -r requirements.txt
3. 환경 변수 — 데모 세트 경로 지정
     COPILOT_DATA_DIR=demo_data
     COPILOT_INDEX_DIR=demo_index
     COPILOT_DERIVED_DIR=demo_derived
4. 색인 재생성 (선택 — 색인 사본이 포함되어 있습니다)
     python -m ingest.build_index
5. 측정
     run_eval_demo.bat      45문항 · 홀드아웃 · 인터락
     python eval/selfcheck.py   시연 전 자기 점검 54항목
6. 실행
     uvicorn api.server:app --port 8000
```

임베딩은 API 또는 로컬 Ollama가 필요합니다. 없으면 어휘 검색만으로 동작하며,
그 경우 화면에 **강등 사유와 영향이 표시**됩니다(측정: lexical 16/45 대
hybrid 28/45). 조용히 나빠지지 않게 하기 위한 표시입니다.
