# 패치 6 — 조치 생성 프롬프트 보정

`graph/advisor.py` 한 파일만 바뀝니다.

## 무엇이 문제였나

```
질의: AIT-4002 "산 잔량이 부족하다고 뜹니다"
출력: 1. DI 수분 저장기 확인   (M9E-3100)
      2. USB 키 공간 확인      (M9E-10053)
```

근거 ID 검증은 통과했습니다. 즉 저 두 항목이 **실제로 검색 결과 안에
있었습니다.** 모델이 지어낸 것이 아니라, 검색이 함께 가져온 근거 중에서
**엉뚱한 것을 골랐습니다.**

이전 프롬프트에는 근거가 순서 없이 나열되어 있었고, "단계는 2~5개"라고
지시했습니다. 그래서 관련 있는 근거가 1~2건뿐일 때 모델이 **개수를
채우려고 무관한 근거를 끌어다 썼습니다.**

## 고친 것

1. **근거에 순위를 붙였습니다.** "관련도 순, 1번이 가장 가까움" 을
   명시하고 번호를 매겼습니다. 1번을 반드시 다루도록 지시합니다.
2. **무관한 근거를 버리도록 지시했습니다.** "검색이 함께 가져온 것일
   뿐 답이 아닐 수 있다" 를 명시하고, 증상에 나온 대상(산/오존/UV
   램프/수지)과 다른 대상은 제외하게 했습니다.
3. **단계 수를 2~5개 → 1~4개로 낮췄습니다.** "쓸 근거가 1~2건뿐이면
   단계도 1~2개만 만들라, 개수를 채우려고 무관한 근거를 넣지 말라" 를
   덧붙였습니다.

## 원인 구분용 옵션

검색이 나쁜 것인지 모델이 잘못 고른 것인지 한 번에 봅니다.

```cmd
python -m graph.advisor --tag AIT-4002 --alarm "산 잔량이 부족하다고 뜹니다" --show-evidence
```

LLM 에 넘긴 근거를 관련도 순으로 먼저 찍고 조치를 생성합니다.

- **근거 1번이 Acid container 계열인데 조치가 엉뚱** → 모델 문제.
  프롬프트 보정으로 개선되어야 합니다. 안 되면 모델을 바꾸십시오.
- **근거 1번부터 DI/USB 계열** → 검색 문제. 조치 생성이 아니라
  검색 쪽을 봐야 합니다.

## 모델을 바꿔야 할 수도 있습니다

qwen2.5:7b-instruct 의 한국어 생성 품질이 높지 않습니다. 실제 출력의
"DI 수분 저장기량 부족" 같은 표현이 그 예입니다. 대안:

```cmd
ollama pull exaone3.5:7.8b        # 한국어 특화 (LG AI연구원)
set COPILOT_MODEL=exaone3.5:7.8b
```

또는 사내 Azure OpenAI 키가 나오면 그쪽이 품질·속도 모두 낫습니다.
조치 생성 제공자는 임베딩과 별개로 설정하므로, 임베딩은 로컬에 두고
조치 생성만 사내 API 로 돌리는 구성도 가능합니다.

```cmd
set COPILOT_PROVIDER=azure
set AZURE_OPENAI_CHAT_DEPLOYMENT=<채팅 배포 이름>
```

## 이 계층은 아직 측정되지 않습니다

45문항·72문항 평가는 검색과 조회를 재는 것이라 조치 생성 품질을
보지 않습니다. 이번 오답도 평가 점수에는 잡히지 않았습니다.

측정하려면 "생성된 단계가 인용한 근거를 실제로 반영하는가", "증상과
무관한 근거를 끌어오지 않는가" 를 보는 별도 평가가 필요합니다.
본선 과제로 두는 것이 맞다고 봅니다.
