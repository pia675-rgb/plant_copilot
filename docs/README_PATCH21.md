# 패치 21 — 카드 상실 시 잃는 채널 노출

## 판넬 계기 목록 제거로 생긴 구멍

판넬의 계기 목록을 없앤 판단 자체는 맞습니다. 카드별로 태그가 보이니
중복이었습니다. 다만 **카드에 인터락이 걸려 있으면 그 카드의 계기 목록이
화면에서 사라졌습니다.**

인터락 표에는 **조건에 걸린 태그만** 나옵니다.

```
CUB-B/R1/S8 는 3점
  AIT-1001   IL-1102-01 조건    → 인터락 표에 보임
  TIT-4004   인터락 무관        → 어디에도 안 보임
  TIT-4008   인터락 무관        → 어디에도 안 보임
```

`lost_tags` 안내는 `dependencies.length === 0` 일 때만 나오므로, 일부만
걸린 카드에서는 나머지가 통째로 빠집니다. "이 카드 내리면 뭘 잃나" 에
대한 답이 반쪽이었습니다.

## 잃는 채널 표를 넣었습니다

`impact()` 가 채널 전체를 싣습니다. `by_card()` 가 이미 채널·서비스·단자를
갖고 있어 새로 읽는 것은 없습니다.

```
잃는 채널 3점
Ch  태그        서비스                      단자      신호        인터락
1   TIT-4008    UPW TANK TEMPERATURE       TB7-10   4-20mA AI   지시·기록만
4 ★ AIT-1001    PRETREATMENT CONDUCTIVITY  TB2-37   4-20mA AI   IL-1102-01
6   TIT-4004    UPW TANK TEMPERATURE       TB6-23   4-20mA AI   지시·기록만
```

채널마다 `interlocks` 와 `safety` 를 붙여서 **"지시·기록만 상실" 과
"보호까지 상실" 이 한눈에** 갈립니다. 태그를 누르면 그 태그로 이동합니다
(`tag-pill` 재사용 — 판넬 목록에서 쓰던 것이 다시 쓰입니다).

인터락 표에는 "의존 인터락" 소제목을 붙였습니다. 표가 셋이 되어 구분이
필요합니다.

CLI 도 같습니다.

```
python -m retrieval.panel_index --card "CUB-B/R1/S8"
```

## 함께 검토한 것 — 이번 업로드의 세 변경

**태그 목록을 IO List 하나로.** 출력을 IO List 의 DO/AO 점으로 흡수한
뒤로 두 목록이 같은 원천이 됐으니 `IO TYPE` 으로 가르는 것이 맞습니다.
instrument 76 / output 24 로 정확히 갈립니다. `"DO" in io_type` 방식이라
`DO16`·`AO-8` 같은 표기가 와도 그대로 동작합니다.

**이력 삭제 복원.** `load_history`/`save_history` 가 캐시를 함께 갱신하므로
삭제 후 재조회가 바로 반영됩니다. 없는 번호는 404 입니다.

**잔상 방지.** `cancelled` 플래그와 `panelReq`/`cardReq` 순번 가드,
`cardImpact.card === card` 확인까지 — 늦게 도착한 응답이 화면을
덮어쓰지 못하게 한 것이 정확한 처방입니다. 이 종류는 화면에 그럴듯하게
보여서 발견이 가장 늦습니다.
