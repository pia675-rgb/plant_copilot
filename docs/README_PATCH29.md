# PATCH 29 — 인터락 후속 질문이 화면 결과를 읽지 못한 결함

2026-08-31

## 문제

사용자가 실사용 중에 발견했다. 인터락을 조회한 뒤 챗봇에 "말로 풀어서
설명 부탁해" 라고 묻자 **엉뚱한 답이 나왔다** — M300 트랜스미터의
Alarm/Clean 메뉴 설정법. 묻지도 않은 다른 기종, 다른 주제였다.

두 번 다시 물어도 같았다. 사용자가 "다른 태그에 대해 이야기한 걸로
보인다"고 지적할 때까지 챗봇은 계속 그 근거로 답했다.

## 원인 — 두 겹이었다

**① `ChatContext` 에 인터락 자리가 없었다.**

챗봇 후속 질문은 "화면에 떠 있는 결과"를 근거로 답한다. 그런데 그
`context` 가 담는 것은 알람 조회 결과(`evidence`)뿐이었다. 인터락을
조회하면 화면은 인터락 탭인데 `context.evidence` 에는 **직전 알람 조회의
매뉴얼 근거가 그대로 남아** 있었다. 챗봇은 그것으로 답을 만들었다.

사용자가 보는 것과 챗봇이 보는 것이 달랐다. 조용히 틀리는 종류의 결함이다.

**② 설명 요청이 후속 질문으로 라우팅되지 않았다.**

후속 질문 판정이 지시 대명사(`조회된 내용`, `방금`, `위의`)에 의존했다.
"말로 풀어서 설명 부탁해" 처럼 가리키는 말이 없으면 안 걸리고 매뉴얼
검색으로 흘렀다. 검색어에 뜻이 없으니 아무 문서나 상위로 올라왔다.

**자유 모드 탓이 아니다.** 근거 모드에서도 같은 일이 난다. 오히려 자유
모드라 「모델 답변 · 문서 근거 아님」 라벨이 붙어 사용자가 알아챘다.

## 무엇을

### retrieval/interlock_describe.py (신규)

인터락 조회 응답을 문단으로 서술한다. **LLM 을 쓰지 않는다** — 인터락은
리스트에서 읽은 사실이고 같은 조회에 같은 문장이 나와야 한다. 모델이
다시 쓰면 조건이 슬쩍 바뀔 수 있고, 그 위험은 정비 지시에서 감당할 수
없다.

- 조건을 한 줄씩. **파싱하지 못한 조건은 원문을 그대로 인용**하고
  자동 해석하지 않았다고 밝힌다
- 태그가 없는 조건(`MOTOR OVERLOAD TRIP (49)`, `E-STOP PB 동작`)은
  원문을 본문으로 쓰고 상태 코드를 괄호로 붙인다. 상태 코드만 남기면
  (`FAULT`, `ESTOP`) 뜻이 사라진다
- 래치 표기를 리스트 그대로. `MANUAL` 은 "사람이 리셋해야 풀린다",
  `AUTO` 는 "조건이 해소되면 스스로 풀린다"
- AND/OR 를 "모두 만족해야 성립 / 하나만 성립해도 동작" 으로 풀어 쓴다
- 출처(도면 번호·시트·PLC 블록)를 각 규칙에 붙인다

### api/server.py

- `ChatContext` 에 `tab`, `interlock` 추가. 어느 탭의 결과인지와 인터락
  응답 원본을 함께 받는다
- 후속 질문 처리에서 **인터락 결과가 있으면 그것으로 답한다.** 인터락
  탭인데 결과가 없으면 "조회한 뒤 다시 물어봐 주세요" 로 안내
- `rule_intent(msg, cur_tag, cur_tab)` — 지시 대명사가 없는 설명 요청도
  후속 질문으로 본다. 단 **조회 대상 낱말(인터락·도면·판넬·반입·사용법)이
  있거나 태그가 있으면 제외** — 그것들은 명령이므로 원래 경로로 간다

### ui/react/src/App.jsx

`InterlockView` 가 조회 결과를 위로 올린다(`onResult`). 알람 뷰와 같은
방식이다.

### eval/selfcheck.py

`인터락 후속 질문 [주입]` 가드. 두 가지를 함께 본다.

1. **라우팅** — 설명 요청 2종이 followup 으로 가고, 조회 명령·사용법·
   알람 조회 3종은 원래 경로를 유지하는가
2. **답의 출처** — 알람 근거를 함께 넣어도 인터락으로 답하는가.
   `IL-5101A-01` 이 답에 있고 `M300` 이 섞이지 않는가. 래치 표기가
   리스트와 일치하는가

## 측정

| 항목 | 결과 |
| --- | --- |
| 인터락 후속 질문 [주입] | 통과 |
| 챗봇 계열 기존 4항목 | 전부 유지 (경로 일치·명령 인식·근거 답변·후속 질문) |
| 45문항 lexical | **16/45 유지** (회귀 0) |
| UI 빌드 | vite 정상 |

검색·판정 코드는 무변경. **로컬에서 전 지표 재측정 필요** —
`run_eval_demo.bat` (28/45 · 2/10 · 67/67) + `python eval\\selfcheck.py`.

## 남긴 것

- 판넬 조회 후의 후속 질문은 아직 화면 결과를 읽지 못한다. 인터락과 같은
  구조로 넓힐 수 있으나 이번 범위에서는 다루지 않았다
- 인터락 서술은 규칙 문장이라 읽기 좋은 산문은 아니다. 정확성을 골랐다

# PATCH 29b — 기능 질문 오인 · 판넬명 조회 크래시 (같은 날 후속)

사용자가 실사용 대화에서 추가로 발견했다.

## 문제 2건

**① 기능에 대한 질문이 명령으로 실행됐다.**
"판넬 조회로 나는 어떤걸 알 수 있지?" → **알람 조회가 실행됐다.**
묻는 사람에게 답 대신 행동이 나갔다. 기능 명사가 있는 문장이 질문인지
명령인지 가리는 규칙이 없어서, 질문이 명령 규칙까지 흘러갔다.

**② 판넬명 챗봇 조회가 죽어 있었다.**
"CUB-A 판넬 조회해줘" → 서버 500. `by_panel` 의 반환 키가
`by_tb → by_terminal` 로 바뀌었는데 챗봇 응답 조립 한 줄만 옛 이름을
읽고 있었다. 기존 가드(판넬 명령 인식)는 라우팅 판정까지만 보고 응답
조립은 안 봐서 잡지 못했다.

## 무엇을 (api/server.py)

- `_FEATURE_Q`(질문 표지) + `_FEATURE_HELP`(기능별 안내 8종) — 기능
  명사와 질문 표지가 함께 있으면 **명령·인사 규칙보다 먼저** 안내로
  답한다. 문장에 태그가 직접 적혀 있으면 조회 의도로 보고 명령 쪽으로
  넘긴다
- 판넬명 응답 조립: `by_tb` → `by_terminal`, 판넬 미존재 시 안내

## 가드 (eval/selfcheck.py)

`기능 질문 라우팅 [주입]` — 질문 5종이 각 기능의 맞춤 안내로 가고,
명령 4종(인터락·알람·판넬명·사용법)은 원래 경로를 유지하며, 판넬명
조회가 예외 없이 처리되는지.

## 측정

라우팅 배터리 17종 전부 기대대로. selfcheck 신규 2 포함 챗봇 계열
전건 통과. lexical 16/45 유지.

# PATCH 29c — 자유 모드가 자유롭지 않았다 · 단자 번호를 몰랐다

사용자가 실사용 대화에서 또 발견했다. 두 건 다 "도구가 아는 것을 못
말하는" 종류다.

## 문제

**① 판넬 조회가 보여준 단자 번호를 되물으면 못 찾았다.**

"CUB-A 판넬 조회해줘" → `IW512+ 1` 처럼 단자 번호가 화면에 나온다.
바로 이어서 "iw512의 태그명은 뭐지?" 라고 물으면 안내문만 돌아왔다.
**방금 자기가 띄운 값을 모르는 셈이었다.** 자료(`by_terminal`)에는
있는데 규칙이 없었다.

**② 자유 모드인데 모델에게 물어보지도 않았다.**

규칙이 못 잡으면 LLM 이 답하도록 `generic` 표식까지 달아 두었는데,
그 앞의 질문 판정(`looks_like_question`)이 **"뭐지·뭐야" 를 질문으로
보지 않았다.** 정규식에 `뭐가`·`뭔` 은 있고 `뭐` 가 없었다. 그래서
자유 모드인데도 모델 답변 없이 안내문만 나갔다 — 사용자가 "자유도가
너무 낮다" 고 한 것이 이것이다.

## 무엇을 (api/server.py)

- **단자 번호 역조회** — `IW512`, `QW034`, `MD100` 형태를 알아보고
  `by_terminal` 에서 태그를 찾는다. 여러 판넬에 같은 번호가 있으면 전부
  보이고, 문장에 판넬명(CUB-A 등)이 있으면 그 판넬로 좁힌다.
  **없는 단자는 지어내지 않고 "찾지 못했습니다" 라고 답한다**
- **질문 판정 확장** — `뭐`, `누구`, `몇`, `되는지`, `맞나` 추가.
  규칙이 못 잡은 질문이 모델에게 넘어간다

## 가드

`단자 번호 역조회 [주입]` — 자료에서 실재하는 단자를 골라 되묻고 태그가
답에 있는지, 없는 단자(IW9999)는 거절하는지.

## 측정

selfcheck 신규 3종(인터락 후속·기능 질문·단자 역조회) 전부 통과,
챗봇 계열 기존 항목 유지, lexical 16/45 유지.

## 남긴 것

자유 모드의 답 품질 자체는 모델 몫이다. 이번 수정은 **모델에게 물어보지도
않던 것을 물어보게 한 것**이지, 답을 좋게 만든 것이 아니다. 조회로 답할
수 있는 것은 규칙이 답하고(단자·판넬·인터락), 나머지가 모델로 간다.
