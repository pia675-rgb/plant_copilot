# 패치 16 — 챗봇 대화 맥락

패치 15 위에 덮으십시오. 패치 7~15 내용을 모두 포함합니다.

## 무엇이 문제였나

```
나:   알람조회하고 알려줘
봇:   AIT-1001 알람 조회를 실행합니다.
나:   조회된 내용을 보고 조치방법을 알려줘
봇:   AIT-1001 알람 조회를 실행합니다.        ← 같은 조회를 반복
```

두 가지가 겹쳤습니다.

1. **대화 맥락이 없었습니다.** 챗봇은 매 메시지를 독립 명령으로 봤고,
   화면에 결과가 떠 있는데 그것을 몰랐습니다.
2. **"조회된 내용" 의 '조회' 가 명령으로 걸렸습니다.** 질문인데 명령
   규칙에 매칭되어 같은 조회를 다시 실행했습니다.

## 고친 것

### 1. 후속 질문을 명령과 분리

`조회된/검색된/나온/방금/위의 + 내용/결과`, `결과를 보고/바탕으로`,
`앞서`, `아까` 가 들어가면 명령이 아니라 **방금 결과에 대한 질문**으로
처리합니다.

`조치|어떻게 해|뭘 해|해결` 도 별도 의도로 뺐습니다. 조치 순서는
조회 결과가 있어야 만들 수 있기 때문입니다.

### 2. 화면 상태를 챗봇에 전달

`/api/chat` 이 `context` 를 받습니다 — 현재 태그, 증상, 판정, 충분성,
그리고 **화면에 떠 있는 근거 목록**입니다.

후속 질문은 **검색을 다시 돌리지 않고 그 근거로** 답합니다.
"조회된 내용을 보고" 라는 요청에는 조회된 그 내용으로 답해야지,
다시 검색해서 다른 근거로 답하면 안 됩니다.

### 3. 두 갈래로 처리

| 질문 | 처리 |
|---|---|
| `조회된 내용을 보고 조치방법을 알려줘` | 조치 순서 생성 (근거 인용 검증) |
| `조치방법 알려줘` | 같음 |
| `방금 결과 설명해줘` | 화면 근거로 질의응답 |
| 조회 결과가 없을 때 | "먼저 알람을 조회해 주세요" 안내 |

## 확인 결과

```
== 조회된 내용을 보고 조치방법을 알려줘  [advice]
   산 계통을 순서대로 확인하십시오.
   1. 산 용기 잔량 확인 — 10% 미만이면 새 용기를 주문하십시오.

== 방금 결과 설명해줘  [followup]
   산 잔량이 10% 미만이면 경보가 뜹니다 [1].

== 조치방법 알려줘 (결과 없음)
   아직 조회 결과가 없습니다. 먼저 태그와 증상으로 알람을 조회해 주세요.
```

## selfcheck 항목 추가

```
[OK] 챗봇 후속 질문   후속 질문을 화면 근거로 처리
```

후속 질문이 명령으로 오인되지 않는지, 결과가 없을 때 안내하는지,
화면 근거로 조치를 만드는지를 봅니다.

## 시연 흐름

이제 이 순서가 자연스럽게 이어집니다.

```
1. AIT-4002 acid residual low 알람 조회해줘
2. 조회된 내용을 보고 조치방법을 알려줘
3. UV 램프는 얼마나 자주 교체하나요?          (매뉴얼 근거 + 출처)
4. LCV-01 인터락 조회해줘                     (원본 블록까지)
```

2번과 3번이 이번 두 패치로 생긴 것입니다.
