## 1. 빠져 있던 도면 층

v1 이 만든 도면 세 종은 **계기 하나를 따라가는** 도면입니다.

| 도면 | 답하는 질문 |
|---|---|
| P&ID | 공정상 어디에 붙어 있는 계기인가 |
| SCHEMATIC | IO 카드 채널부터 로컬 계기까지 어떻게 결선되어 있나 |
| OUTLINE | 그 단자대가 판넬 **안**의 어디에 박혀 있나 |

한 층이 없습니다. **그 판넬 자체가 현장 어디에 있는가.** 정비원이 실제로
이동하는 대상은 계기가 아니라 판넬입니다.

> `DEMO_OUTLINE.pdf` 가 "PANEL GENERAL ARRANGEMENT" 라는 제목을 달고
> 있지만 내용은 판넬 정면도(DIN 레일·단자대 배치)입니다. 이름이 겹치면
> 시연 중에 헷갈리므로 새 도면은 `ARRANGEMENT` 로 구분했습니다.

`data/make_arrangement.py` 가 계기 리스트의 `PANEL` 열에 **실제로
나타나는 판넬만** 읽어서 A3 2매를 그립니다. 1매는 배치 평면도(전기실 +
공정구역, 설비 윤곽, 케이블 트레이, 방위·축척·그리드 A~H/1~5),
2매는 판넬 일람표입니다.

같은 실행에서 `PANEL_LOCATIONS.csv` 가 함께 떨어집니다. **도면과 조회
결과의 원천이 하나**여야 둘이 어긋나지 않기 때문입니다. 계기 리스트에는
있는데 배치도에 정의되지 않은 판넬이 있으면 생성 시 경고를 찍고,
`/api/health` 의 `panels_unlocated` 로도 드러납니다.

v2 가 만든 도면이므로 v2 `data/` 에 둡니다. v1 의 `drawings_index.csv` 는
고치지 않고, `/api/instrument/{tag}` 가 응답을 만들 때 ARRANGEMENT 항목을
얹습니다.

## 2. ★ 알맹이는 도면이 아니라 역조회입니다

`PANEL` 열은 태그→판넬 방향뿐 아니라 **판넬→태그** 로도 읽힙니다.
판넬은 공정 단위가 아니라 배선 편의로 묶여 있어서, 판넬 하나에 물린
계기가 여러 시스템에 흩어집니다. 이 범위를 사람이 세면 반드시
빠뜨립니다.

```
CUB-B 를 내리면
  계기 21점 상실 · 7개 시스템에 분산
  의존 인터락 10건 (안전 인터락 7건) · 영향 출력 7건
  인터락 무관 15점 — 지시·기록만 상실
```

## 3. ★ 판정하는 것과 판정하지 않는 것

판넬을 잃으면 그 판넬에 결선된 계기 값이 무효가 됩니다. 그 다음 PLC 가
어떻게 동작할지는 **대체값(substitute value) 정책**에 달려 있고, 그건
인터락 리스트에도 계기 리스트에도 없습니다. 그래서 **트립 여부를
단정하지 않습니다.** 리스트만으로 확실히 말할 수 있는 것만 말합니다.

| 말하는 것 | 근거 |
|---|---|
| 어떤 인터락이 이 판넬 신호에 의존하는가 | 조건 태그 ∩ 판넬 태그 |
| 그 의존이 조건 전체인가 일부인가 | 조건 태그 집합 포함 관계 |
| 남는 보호가 있는가 | LOGIC 열 (AND 는 하나만 잃어도 성립 확인 불가) |
| 바이패스 가능한가, 안전 인터락인가 | BYPASS / KIND 열 |

계기 **단품 고장**은 다른 시나리오입니다. `FAULT MODE` 열
(Upscale 22mA self-diag / Downscale NAMUR)에 방향이 적혀 있으므로
어느 조건이 성립하는지까지 말할 수 있습니다. `fault_effect()` 가
그쪽을 담당하고, 두 시나리오를 섞지 않습니다.

```
LIT-4003 (Downscale) 고장 → 하한으로 튐
  IL-4102-01  XV-4102 CLOSE   성립  (LL 조건)
  IL-5101A-01 P-5101A STOP    성립  (LL 조건)
AIT-4001 (Upscale) 고장 → 상한으로 튐
  IL-4101-01  XV-4101 CLOSE   미성립 (< 17 Mohm-cm 는 반대 방향)
```

이 구분이 없으면 "판넬이 죽으면 FAULT MODE 방향으로 트립된다" 는
틀린 결론이 나옵니다. 계장 담당자가 보면 바로 티가 나는 종류의 오류라
선을 그어 두었습니다.

## 4. 평가 — 119문항, 그리고 변이 시험

인터락 평가와 같은 원칙입니다. 정답을 **원천(계기 리스트 · 배치 CSV ·
인터락 엑셀)에서 직접 계산**하고 `PanelIndex` 의 출력을 쓰지 않습니다.

```
locate 72 · place 5 · roster 5 · scope 5 · depend 5 · fault 20 · absent 7
전체 119/119
```

그런데 **만점은 그 자체로 아무것도 증명하지 않습니다.** 채점이 실제로
무언가를 붙잡고 있는지 보려면 로직을 망가뜨렸을 때 무너져야 합니다.

| 변이 | 무엇을 껐나 | 전체 | 무너진 항목 |
|---|---|---|---|
| no-location | 배치 CSV 를 비움 | 114/119 | place 5/5 → **0/5** |
| no-logic | AND/OR 결합을 무시 | 115/119 | depend 5/5 → **1/5** |
| no-direction | FAULT MODE 방향을 무시 | 109/119 | fault 20/20 → **10/20** |

`no-direction` 이 절반만 무너지는 것은 정상입니다. 방향을 UPSCALE 로
고정했으므로 원래 UPSCALE 인 계기 32점은 그대로 맞습니다. 이 숫자를
그대로 남겨 둡니다.

`locate` 72문항은 사실상 통과 매핑이라 난도가 없습니다. 넣어 둔 이유는
**실물 계기 리스트로 교체할 때 컬럼 구조가 달라지면 여기서 먼저 깨지기**
때문입니다.

## 5. 챗봇 — 표기 충돌 처리

판넬명(`CUB-B`, `RIO-01`)은 태그와 표기가 겹칩니다. `find_tag` 가 먼저
돌면 `RIO-01` 을 없는 태그로 보고 "리스트에 없습니다" 를 반환합니다.
그래서 **판넬 판정을 태그 판정보다 앞에** 두었습니다.

```
CUB-B 내리면 뭐가 죽어?      → 상실 영향 (수치 포함 답변 + 판넬 탭 이동)
AIT-1001 은 어느 판넬이야     → 판넬·그리드·단자대·슬롯/채널
RIO-01 판넬에 뭐가 물려 있어  → 시스템별 계기 수
LIT-4003 고장나면 어떻게 돼   → 방향과 성립 조건
XV-4101 인터락 조회해줘       → (기존 그대로) 인터락
```

selfcheck 에 **판넬 규칙이 인터락 명령을 가로채지 않는지** 확인하는
항목을 넣었습니다. 규칙을 앞에 끼워 넣을 때 생기는 전형적인 회귀입니다.

## 6. 실패를 삼키지 않게

오늘까지 반복된 유형이라 같은 원칙을 적용했습니다.

- `get_panel()` 은 실패하면 사유를 남기고 `/api/health` 의
  `panel_index_error` 로 드러냅니다. 판넬 조회가 통째로 안 뜨는데
  이유를 알 수 없는 상태를 만들지 않습니다.
- `/api/health` 에 `panels`, `arrangement_pdf` 존재 여부,
  `panels_unlocated` 를 함께 싣습니다.
- 화면은 배치 정보가 없으면 그 사유와 조치 명령을 배너로 띄웁니다.

## 7. selfcheck 4항목 추가 (14 → 18)

```
판넬 평가셋              119문항 통과 여부
판넬 배치도 검색         판넬명이 PDF 안에서 실제로 찾아지는가
                        (못 찾으면 하이라이트가 안 걸립니다)
판넬 트립 단정 금지 [주입]  '트립됩니다' 류 단정이 새로 들어오면 실패
판넬 명령 인식           판넬 규칙이 인터락 명령을 가로채지 않는가
```

세 번째가 [주입] 인 이유는, 근거 없는 단정은 코드가 커지면서 슬며시
들어오는 종류의 퇴행이기 때문입니다. 문구를 지키는 장치를 두었습니다.

## 8. 4D 리포트

판넬 칸에 배치 그리드를 함께 찍습니다.

```
판넬 / 단자    CUB-B (B5) / TB2-37
```

이 한 줄이면 현장 이동이 끝납니다. 칸을 늘리지 않아 기존 레이아웃은
그대로입니다.

## 남은 것 — 데이터 확인이 필요합니다

배치도의 구역 배치는 **가정**입니다. `RIO-02` 는 실제로
DISTRIBUTION 4 / PRETREATMENT 4 / RECLAIM 1 / RO 2 로 섞여 있는데
도면에는 "PROCESS AREA - WEST" 한 곳에 두었습니다. 판넬 위치가
공정 구역과 1:1 이 아닌 것 자체는 사실이지만, 실제 프로젝트에서
위치를 어떻게 표기하는지(그리드 좌표인지, 전기실 번호인지) 확인되면
`PANELS` / `AREAS` 상수만 고치면 됩니다. 그 아래 조회·평가는 그대로
따라옵니다.
