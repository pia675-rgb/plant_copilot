## 3. 작업 방식 (반드시 유지)

- 사용자는 한국어, Windows/cmd. 코드는 샌드박스에서 검증 후 `/mnt/user-data/outputs`로
  내보내면 사용자가 로컬에 덮어쓰고 실행·확인.
- **함정 5개**:
  1. `App.jsx`/`index.css` 수정 시 **`npm run build` 필수**
  2. `server.py`는 서버 재시작만, 빌드 불필요
  3. FastAPI 라우트는 등록 순서 매칭 — `/api/history/stats`는 `{tag}`보다 먼저
  4. 문자열 표식으로 파일 수정 시 표식이 파일 내 유일한지 확인 (사고 2회)
  5. **집 PC에는 `data/`(실물)가 없다.** `run_check.bat`·`run_eval.bat`은 실물 전용이라
     집에서 돌리면 `demo/sources`(76점)로 흘러가 16건이 실패한다 — 코드 문제 아님.
     집에서는 **`run_eval_demo.bat`**, selfcheck는 데모 변수를 걸고 실행할 것.
  6. **0이 유효값인 칸에 `str(v or '')` 금지** — IO List CH=0을 삼킨 falsy-zero
     버그가 실제로 있었음 (패치 27에서 정정)
- 원칙: "판정하지 않는다", "느린 것과 조용히 틀리는 것 중 느린 쪽", 정해진 사실은
  모델이 덮지 않는다, 되돌릴 수 없는 조작 금지, **수치는 측정으로만 말한다**,
  검색 점수 튜닝 금지, `COPILOT_DIVERSIFY=off` 유지(측정 기각: off 33 > kind 29 > all 27).

배경: SCADA 실제 알람(HH/LL/LOOP ERROR/ON·OFF COMMAND + SSL 코드)이 매뉴얼에
**0건**(실측)이라 어휘가 어긋나 있었음. 입력은 2단계(원격 SCADA / 현장 계기 화면).

1. **SSL 16진 코드 조회** — `bm25.exact_code`에 `[0-9][0-9A-Fa-f]{0,3}H` 추가,
   카드 코드 24종 전부 조회(11H→Supply voltage missing). 태그 숫자부(4002) 오인 방지.
2. **알람 라우팅** — `retrieval/alarm_rules.py` 신규. 알람 5종 식별 + 카드
   진단표·트러블슈팅 표제어로 확장. 확장 시 알람명 자체는 검색어에서 제외
   ("loop"는 M9e에서 수처리 배관 — false friend). LOOP·SSL은 카드 상한 해제.
   채점 질의를 실제 검색어로 바꿔 "정답 찾고도 거절"하던 구조 해소.
   trace에 `alarm-route:` 1줄. **평가 448문항 발화 0건**(오염 없음, 가드로 상시 감시).
3. **알람 폭주 역추적** — `siblings(tag)` + `common_cause_of(tags)`
   (card→rack→panel→plc→scattered 4계층, uncovered/unknown 분리).
   diagnose 응답 `card_siblings` + 신규 `GET /api/common-cause-of?tags=…`.
   4D PDF D2에 동반 태그 줄. UI 화면은 없음(dist 미수정) — API·PDF로 노출.
4. **4D D3 정직성** — 매뉴얼 근거 없으면 "없음 — 이력 기준으로 판단" 명시.
5. **IO_LIST 채널 중복 7건 재배정** (잔존 0) + selfcheck 가드 4종
   (`c_ssl_code_lookup`, `c_alarm_rules_inert`, `c_io_channel_unique`, `c_flood_reverse`).
6. **시연 시나리오** — `docs/SCENARIO_SCADA.md`. 8/27 hybrid 실측 반영본:
   장면1 `loop error` → advise 0.93, 1위 ET200SP Supply voltage missing(p.54),
   5위 M9e p.274 (카드 4 + 계기 1 구성) / 장면2 `no power` → advise 1.00, p.274 3위
   (라우팅 미발화가 정상 — 알람명이 아닌 현장 증상) / 장면3 폭주 5태그 → card,
   4태그로 줄이면 `uncovered:["FIT-2004"]` 반례 표시.
7. **27b(현장 시험 중 발견·수정)**: 판별이 대문자 원문만 봐서 소문자 `loop error`가
   라우팅을 비껴갔음. 화면에는 충분성 1.00으로 System Error 공통 설명·DI loop 절이
   올라오는 **자신 있게 어긋난** 상태였음. 구문형(loop error/high high/low low/
   on·off command)은 대소문자 무시로 넓히고 축약형 HH/LL만 대문자 유지.
   넓힌 뒤 발화 0건·lexical 16/45 재확인.
8. 직전 세션의 fourd 건(4D 기입란 통합 + 이력 통계)은 **이 작업본에 이미 반영됨**.

측정: lexical 16/45(기준선 그대로) · exact_code 448문항 변화 0 · 4D PDF 2종 생성 확인.
selfcheck 실패 4건 분류 완료 — 3건은 임베딩 키 없는 창의 dense 강등 연쇄(정상),
1건은 테스트 env 오류(`COPILOT_PROVIDER=none`은 없는 값, `off`가 맞음).

정정 2건 기록됨(README_PATCH27): DIVERSIFY 켜자던 제안 철회(측정 기각 확인) /
