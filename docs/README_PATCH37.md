# 패치 37 — L1 IO LIST 표준양식 대응 · 공정 모의 화면 생성

2026-09-24 · 본선 이후 개선 1차

## 무엇을 했나

### 1. L1 IO LIST 표준양식 읽기

`ingest/io_standard.py` 신설. L1 양식이면 읽는 즉시 내부(24종) 이름으로 옮긴다.
이 모듈 밖의 코드는 두 양식을 구별하지 않는다.

**이름이 같고 뜻이 다른 열이 둘 있다.** 이름대로 읽으면 에러 없이 틀린다.

| 열 | 24종의 뜻 | L1 의 뜻 | 처리 |
| --- | --- | --- | --- |
| `PLC` | 제어기 이름 | 제어 유형(DI·COM·PID) | `PLC TYPE` 으로 비키고 `CPU` 를 `PLC` 로 |
| `UNIT` | 공학 단위 | 공정 대분류(RO·UF) | `PROCESS UNIT` 으로 비키고 단위는 `RANGE (단위)` 에서 |

그 밖의 대응: `AREA→LOCATION` · `PN→PN(DP)` · `P&ID No.→DWG No.` · `MARK→SIGNAL TYPE1` ·
`Instrument Power→POWER SOURCE` · `DB BIT/BYTE→BIT/BYTE` · `I/O(AI-4)→IO TYPE(AI)` ·
`RANGE (단위)(0~100%)→RANGE MIN/MAX·UNIT`.

- RACK 열은 L1 에 없다. 가이드 PN 규칙(「RACK당 1씩 연번 증가」)대로 PN 이 랙을 대신하고
  RACK 은 0 으로 둔다. 카드 식별 (판넬, PN, 랙, 슬롯)의 유일성은 PN 이 만든다
- 가이드 시트에도 TAG 머리가 있다 — `IO LIST` 시트를 먼저 고른다
- 같은 처리를 `ingest/repair.py`(채널 중복·헤더 교정)와 `ingest/inspect.py`(반입 점검)에도.
  24종 기준으로 대조하면 헤더 교정이 **멀쩡한 L1 열을 24종 이름으로 바꾸자고** 제안한다
- `tools/convert_io_to_l1.py` — 24종 → L1 이관 겸 회귀 시험 도구

### 2. 공정 모의 화면 (`sim/`)

화면승인자료 캡처 → 모의 화면. 판단은 규칙, 옮겨 적기만 모델 (CLAUDE.md 5).

```
캡처 이미지 ─GPT-5.5─▶ layout.json ─규칙─▶ model.json ─고정 렌더러─▶ screen.html
                        (심볼·태그·위치)    (인터락·IO 대조)
```

| 파일 | 역할 |
| --- | --- |
| `sim/extract.py` | 비전 모델로 **보이는 것만** 옮겨 적음. 없는 태그는 null |
| `sim/model.py` | 기존 인터락 파서 결과 + IO List + 계기 리스트를 규칙으로 대조 |
| `sim/template.html` | 렌더러 + 모의 엔진 + 조건 점검 (자체 완결 HTML) |
| `sim/store.py` | `<DERIVED_DIR>/sim/<id>/` 저장·재생성 |
| `api/sim_routes.py` | 새 엔드포인트만. 쓰기는 반입 열쇠를 거친다 |
| `ui/react/public/sim_studio.html` | 업로드·목록·배치 수정 화면 (「공정 화면」 탭) |

지어내지 않기 위해 둔 것:

- 조건·설정값·지연은 인터락 리스트 원문에서만. `trace_problems()` 가 모든 조건을
  원문으로 되짚고 설정값 숫자가 원문에 있는지 본다. 실패하면 경고로 뜬다
- 해석 못 한 조건은 버리지 않고 **원문 그대로 수동 토글**
- 리스트에 없는 화면 태그는 「미확인」. 비슷한 태그는 후보만 보이고 바꾸지 않는다
- 범위를 모르는 계기는 「범위 미상 — 임시」
- 리스트에 없는 동작 규칙(자동 기동 조건 등)은 「가정」 으로 화면 상단에 적는다
- PID·조절밸브는 표시용 모의이며 인터락 판정에 쓰지 않는다고 화면에 적는다

엔진 규칙은 수작업 P-5101A 화면에서 가져와 일반화했다: 인터락(래치=RESET MANUAL),
허가는 기동 시점에만, 시퀀스 정지는 원인 해소 시 자동 복귀, 지연 타이머.

### 3. 연결

- 「공정 화면」 탭 추가
- 인터락 조회: 조회한 출력 태그가 **실제로 들어 있는** 모의 화면이 있을 때만 공정 화면
  패널을 띄우고 그 심볼을 선택해 둔다. 없는 태그에 다른 화면을 여는 것은 금지(패치 33b)

## 도중에 고친 것 (난관기록 후보)

1. **교대 운전 동시 기동.** 조건을 틱 첫머리 상태로 판정해 A·B 가 같은 틱에 함께 섰다.
   다른 장치 상태를 보는 조건은 그 장치를 판정하는 순간 다시 본다
2. **기동 직후 래치.** 전 장치가 꺼진 첫 순간 「모두 정지」 인터락이 래치됐다. 한 번 돌린 뒤
   지금 성립하지 않는 래치만 풀고 출발한다 (운전원의 기동 후 리셋)
3. **허가 점검 FAIL 3건 — 점검 쪽 결함.** AND 허가를 한꺼번에 깨서 VFD FAULT 인터락까지
   같이 걸렸다. 하나씩 깨고, 되돌린 뒤 리셋하고 다시 명령한다. 기저에서 허가가 원래
   서 있지 않은 것(교대 운전 B호기)은 FAIL 이 아니라 SKIP 과 그 이유로
4. **엔진 가드 동어반복.** 모델의 래치를 지우는 주입은 기대 동작도 같이 바뀌어 통과했다.
   주입을 엔진 코드에 심는 것으로 바꿨다

## 37b — MAXIS 노드 대응 (같은 날 추가)

- **화면 추출 전용 키·주소** `COPILOT_SIM_API_KEY` · `COPILOT_SIM_BASE_URL`. 배포판 공용 `OPENAI_*` 는
  DeepInfra 를 가리키므로, 분리하지 않으면 DeepInfra 에 gpt-5.5 를 요청한다
- **비동기 추출** `POST /api/sim/jobs` → `GET /api/sim/jobs/{id}` 폴링. 노드 게이트웨이 15초 벽 때문.
  화면은 비동기판만 쓴다
- **업로드 전 축소** 긴 변 2400px · 1.5MB 초과 캡처는 브라우저에서 줄여 올린다 (게이트웨이 본문 제한 대비)
- 노드 반영 절차: `docs/MAXIS_DEPLOY_PATCH37.md`

## 사용

```cmd
:: GPT-5.5 키
set OPENAI_API_KEY=...
set COPILOT_SIM_MODEL=gpt-5.5
:: 사내 Azure 면
set COPILOT_SIM_PROVIDER=azure
set COPILOT_SIM_MODEL=<배포 이름>

:: 명령줄
python -m sim --image 화면승인자료.png --title "NW 탱크"
python -m sim --layout demo\sim\layout_P5101_demo.json --title "P-5101A 대조"
python -m sim --rebuild <id>      :: 리스트가 바뀐 뒤
```

화면에서는 「공정 화면」 탭 → 이미지로 생성. 태그를 잘못 읽었으면 「배치 수정」 에서 고치고 저장.

## 하지 않은 것

- 공정 동특성(펌프가 돌면 수위가 내려가는 등) — 수위는 슬라이더. 근거 없는 물리를 넣지 않음
- 챗봇 명령 연결(「NW 화면 열어줘」) — tools.py 에 한 곳 등록이 필요, 다음 패치
- 실물 GPT-5.5 판독 품질 측정 — 키가 있는 환경에서 캡처 여러 장으로 태그 판독률을 재야 함
