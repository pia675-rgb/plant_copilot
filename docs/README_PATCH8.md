# 패치 8 — 같은 유형의 결함 전수 점검

```
api/server.py       챗봇 게이트웨이 통합, /api/chat/status 실측화, 예외 은폐 제거
graph/advisor.py    (패치 7 내용 포함)
eval/selfcheck.py   (신규) 고장 주입 포함 전 경로 점검
```

## 이번 결함의 성격

지금까지 세 번 같은 유형으로 깨졌습니다.

| 사건 | 공통점 |
|---|---|
| 임베딩 캐시가 다른 모델 것이어도 재사용 | 실패해도 화면이 그럴듯함 |
| 조치 생성 LLM 이 없어도 근거 나열로 폴백 | 실패 사실이 눈에 안 띔 |
| 긴 ID 를 모델이 못 옮겨 적어 전 단계 폐기 | 실패해야 알 수 있는 가정 |

**실패해야 알 수 있는 가정**이고, 실패해도 화면이 그럴듯해서 알기
어렵다는 것이 공통점입니다. 그래서 두 갈래로 손봤습니다 — 같은 유형이
남아 있는 곳을 찾아 고치고, 앞으로는 시연 전에 드러나게 만들었습니다.

## 찾아서 고친 것

### 1. 챗봇이 조치 생성과 다른 규칙을 쓰고 있었습니다 (중대)

```python
use_llm = req.use_llm and provider in ("openai","azure","llm") and bool(api_key)
```

`COPILOT_PROVIDER` 를 두 곳에서 읽는데 **뜻이 달랐습니다.** 조치 생성은
`ollama` 를 인정하고 챗봇은 인정하지 않습니다. `run_claude.bat` 에
`COPILOT_PROVIDER=ollama` 를 넣은 순간 조치 생성은 켜지고 **챗봇만
조용히 규칙 엔진으로 떨어졌습니다.** 화면 어디에도 그 사실이 나오지
않았습니다.

게이트웨이를 `graph/advisor.py` 하나로 합쳤습니다. 이제 설정 하나가
두 기능을 함께 켜고, 안 켜지면 사유(`llm_reason`)가 응답에 실립니다.

덤으로 챗봇이 태그를 지어내면 규칙 추출 결과로 덮어씁니다.

### 2. `/api/chat/status` 가 설정만 보고 있었습니다

환경변수만 확인해 `llm_ready` 를 돌려줬습니다. 모델을 안 받아 둔
상태에서도 준비된 것처럼 보입니다 — 조치 생성이 404 로 떨어진 것이
정확히 그 경우였습니다. 이제 실제로 한 번 호출해 보고 판단합니다.

### 3. 예외를 삼키는 곳

`load_interlock_tags()` 에 `except Exception: pass` 가 있었습니다.
인터락 태그 목록이 반쪽인 채로 화면에 나가도 알 수 없습니다. 목록은
그대로 돌려주되 실패 사실을 `/api/health` 의 `interlock_tag_error` 로
드러냅니다.

## 앞으로 시연 전에 드러나게 — eval/selfcheck.py

`preflight` 는 "환경이 갖춰졌는가"를 봅니다. 이 스크립트는
**각 경로가 실제로 동작하는가, 실패했을 때 그 사실이 드러나는가**를
봅니다.

```cmd
python -m eval.selfcheck
python -m eval.selfcheck --skip-llm     # 모델 없이 구조만
```

| 항목 | 무엇을 보는가 |
|---|---|
| 검색 모드 구성 | lexical·hybrid 가 강등 없이 도는가 |
| 한글 질의 도달 | 한글 증상이 영문 매뉴얼에 닿는가 (v2 논지) |
| 근거 없을 때 거절 | **거절 사유가 벤더 문서 게이트인가** |
| 다양성 설정 | 기각된 설정이 켜져 있지 않은가 |
| 임베딩 캐시 신원 [주입] | 다른 모델 서명을 주면 거부하는가 |
| 환각 차단 [주입] | 없는 근거를 인용하면 버리는가 |
| 챗봇·조치 경로 일치 | 같은 제공자 설정을 쓰는가 |
| 규칙 엔진 명령 인식 | 모델 없이도 명령을 알아듣는가 |
| 인터락 72문항 | 층 분리·부재 판정·원문 보존 |
| 한글 PDF 폰트 | Helvetica 로 떨어지지 않는가 |
| 조치 생성 실행 | 실제 모델로 단계가 나오는가, 버려진 단계가 없는가 |

### [주입] 표시가 붙은 항목이 핵심입니다

정상 동작만 보면 검출 장치가 고장 났을 때 알 수 없습니다. 그래서
일부러 고장을 넣고 **잡히는지**를 확인합니다.

- 임베딩 모델 서명을 가짜로 바꾸고 → 캐시를 거부하는지
- 없는 근거를 인용하는 응답을 넣고 → 단계를 버리는지

### 허위 통과도 잡습니다

`근거 없을 때 거절` 항목이 처음에는 검색이 죽어서 생긴 거절까지
통과시켰습니다. 거절했다는 사실만 봤기 때문입니다. 지금은 `grade_parts`
에 벤더 문서 게이트가 찍혔는지까지 확인합니다.

## 권장 사용

시연·평가 직전에 두 개를 순서대로 돌리십시오.

```cmd
python -m eval.preflight     # 환경이 갖춰졌는가
python -m eval.selfcheck     # 경로가 실제로 도는가
```

전자가 통과하고 후자가 실패하면, 환경은 맞는데 로직이 깨진 것입니다.
