# 패치 15 — 챗봇을 문서 근거 질의응답으로

패치 14 위에 덮으십시오. 패치 7~14 내용을 모두 포함합니다.

```
graph/qa.py              (신규) 문서 근거 질의응답
api/server.py            챗봇에 QA 경로 연결
config.py                COPILOT_CHAT_QA 스위치
ui/react/src/App.jsx     답변에 출처 표시
ui/react/src/index.css   출처 스타일
eval/selfcheck.py        QA 회귀 검사 추가
```

## MAXIS 처럼 만들려면 무엇이 필요한가

"사양서를 넣고 지시문을 넣는다" 가 핵심인데, **그 부품은 이미 다
만들어져 있었습니다.** 하이브리드 검색, 근거 충분성 판정, 근거 ID
검증까지요. 챗봇이 그것을 안 쓰고 명령 해석만 하고 있었을 뿐입니다.

이제 세 층을 함께 넣습니다.

1. **지시문** — 이 도구가 무엇이고 무엇을 하면 안 되는지
2. **사양서** — 질의에 태그가 있으면 그 계기의 제조사·모델·계통·신호·범위
3. **근거** — 하이브리드 검색이 찾아온 매뉴얼 청크 (번호로 인용)

## 일반 챗봇과 다른 점

여기가 이 프로젝트의 논지와 이어지는 대목입니다.

- **근거 충분성이 임계값에 못 미치면 답을 만들지 않습니다.** 알람
  조회와 같은 판정을 그대로 씁니다.
- **각 문장이 근거 번호를 인용해야 하고, 검색 결과에 없는 번호를
  인용한 문장은 버립니다.**
- 남는 문장이 없으면 역시 모른다고 합니다.
- 답변 아래에 **출처(문서·페이지)가 표시됩니다.**

### 검증한 동작

없는 근거 `[9]` 를 인용한 문장을 섞어 넣어 시험했습니다.

```
모델 출력: "잔량이 10% 미만이면 경보가 뜹니다 [1].
            펌프를 분해하십시오 [9]."
화면 출력: "잔량이 10% 미만이면 경보가 뜹니다 [1]."
           [1] Acid container · m9.pdf p.400
```

지어낸 문장이 화면에 도달하지 않습니다. 근거가 아예 없으면
"매뉴얼에서 근거를 찾지 못했습니다" 로 답합니다.

## 무엇이 QA 로 가는가

명령(`인터락 조회`, `알람 조회`, `사용법`)은 그대로 규칙 엔진이
처리합니다. 그 외에 **질문 형태**로 보이는 문장만 QA 로 갑니다.

```
"UV 램프는 얼마나 자주 교체하나요?"   → QA (매뉴얼 근거로 답변)
"전도도 센서 교정 절차 알려줘"        → QA
"LCV-01 인터락 조회해줘"             → 규칙 (화면 실행)
"안녕"                              → 일반 대화
```

끄려면 `set COPILOT_CHAT_QA=0` 입니다.

## 응답 속도

QA 는 검색 + LLM 생성이라 CPU 에서 10~30초 걸립니다. 명령 실행은
규칙 엔진이라 즉시입니다. 시연에서 QA 를 보여주실 거면 질의를 미리
한 번 돌려 모델을 메모리에 올려 두십시오.

## selfcheck 항목 추가

```
[OK] 챗봇 근거 답변 [주입]   인용 검증 / 근거 없을 때 거절
```

## 모델 품질에 대해

한국어 문장 품질이 아쉬우면 모델을 바꾸십시오.

```cmd
ollama pull exaone3.5:7.8b
set COPILOT_MODEL=exaone3.5:7.8b
```

다만 **"오늘 날짜를 모른다" 는 모델 성능 문제가 아닙니다.** LLM 은
시계를 갖고 있지 않아 프롬프트에 넣어주지 않으면 어떤 모델도
모릅니다. 사내 API 로 바꿔도 같습니다.
