# 패치 26 — 부속 데이터 폐지

## 네 항목을 모두 업로드 자료에서 읽습니다

`TAG_ATTRIBUTES.xlsx` 는 제가 만든 파일이었습니다. 프로젝트 산출물이
아니라서 실물 전환 시 채울 곳이 없었고, 데모에서는 채워지고 실물에서는
비는 상태가 화면에 드러나지 않습니다. 없앴습니다.

```
TERMINAL       TB List
TYPE           계기 리스트 SENSOR TYPE
FAIL POSITION  인터락 리스트 "* Valve Action : Fail Open"
MANUAL FILE    계기 리스트 MODEL ↔ 매뉴얼 파일명 대조
```

## 1. TB List 리더가 두 양식을 읽습니다

주신 `PLC_TB_Layout.xlsx` 는 앞서 주신 SPHA4 판과 표기가 달랐습니다.

```
SPHA4   "DI-32  (32CH TB)"      하이픈·설명 붙음
신규    "DI32" · "AI4-4W"       붙여 씀, 결선 방식이 뒤에
```

블록 머리 정규식을 넓히고, TB 라벨을 블록 폭 안에서 찾도록 바꿨습니다.
카드 위치 표기(`D03-S01`)도 함께 읽습니다. 두 파일 다 정상입니다.

판넬명이 `('CPU 315-2',)` 처럼 파이썬 튜플 문자열로 들어오는 경우도
정리했습니다.

**단자와 태그를 구분하는 문제**가 하나 있었습니다. 뒤에서부터 "태그처럼
생긴 것" 을 찾으면 `TB9-1` 같은 단자 번호를 태그로 잡습니다. 실제로
그렇게 잘못 읽혔습니다. 단자·주소를 먼저 빼고 남은 것에서 태그를 고르게
했고, 단자는 현장 번호(`TB2-37`)를 카드 단자(`IW510+`)보다 우선합니다.

## 2. 데모 TB List 생성기 (`tools/make_tb_list.py`)

데모에는 TB List 가 없어 단자가 부속 데이터에서만 왔습니다. IO List 를
읽어 mastertool 격자 양식으로 만듭니다.

```
판넬 6 · TB 블록 36 · 채널 100 (단자 있는 채널 76)
※ 단자 번호가 없는 채널 24점은 비워 두었습니다 — 지어내지 않습니다
```

**단자 번호를 새로 만들지 않습니다.** IO List 에 있는 값을 옮기기만
합니다. 지어낸 번호로 도면을 하이라이트하면 없는 자리를 가리킵니다.

## 3. 데모 인터락 리스트에 Valve Action 추가

말씀하신 대로 실물 인터락 리스트는 REMARK 자리에 적습니다.

```
* Valve Action : Fail Open
```

데모 생성기가 같은 표기를 쓰게 하고, 데모 파서도 그 문구를 읽게 했습니다.
**별도 열을 만들지 않았습니다** — 열을 만들면 실물과 모양이 달라지고
파서가 두 벌이 됩니다.

## 4. 밸브·펌프 종류

계기 리스트의 `SENSOR TYPE` 자리에 들어갑니다(`ON-OFF VALVE` · `PUMP`).
출력 원천이 그 값을 갖고 있어 생성 시 옮기게 했습니다.

## selfcheck 35 → 36

```
부속 데이터 폐지 [주입]   TAG_ATTRIBUTES 가 되살아나지 않았는가
                         네 항목이 실제로 채워지는가
```

파일이 없는지만 보지 않습니다. **파일만 없애고 값이 비면 고친 것이
아닙니다.** 네 항목의 채움 수를 함께 확인합니다.

```
부속 없음 / 단자 100 · 종류 100 · 매뉴얼 32 · 고장위치 18
```

매뉴얼 32건은 `M300`·`M9e` 두 기종에 해당합니다. `TX-2000` 은 매뉴얼이
없는 기종이라 비는 것이 정상입니다 — 벤더 문서 게이트가 거절하는
대상입니다.
